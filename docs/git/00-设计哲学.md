# 第 00 章 · 设计哲学：Git 到底在存什么

> 本章**一个命令都不教你**（`git init` 都没有）。
> 但读完它，后面每一章的"为什么非得这么用"你都能自己想出来。
>
> 本章你需要记住的就一件事：**Git 不是保存你的文件，是保存一个"内容寻址的对象数据库"——你的整个项目历史，是几百上千个小对象通过哈希串起来的一张网。**

---

## 0.1 先问你一个问题

假设你已经会用一点 Git——会 `git add`、`git commit`、`git push`，能把它当"高级网盘"用。

现在问你一个问题：

**你最近一次 `git commit` 的时候，Git 到底往磁盘上写了什么？**

大多数人会愣住，然后猜一个答案："把这次改了哪些行，存下来了吧？"

这个直觉非常自然，因为**我们人脑里"版本"就是这么理解的**：

> 第 1 版写了 A，第 2 版改了 B 行，第 3 版删了 C 行……
> 所以要保存历史，就是保存"每一次改动的清单"。

这个模型叫**「差异存储」（delta-based）**。很多老版本控制系统（比如 SVN、CVS）真的是这么干的：

```
rev 1：文件内容 = "hello"
rev 2：diff = 第 1 行 "hello" → "hello world"   （只存这个"改动"）
rev 3：diff = 删掉末尾的 " world"
```

你要拿到 rev 3 的内容，得从 rev 1 开始，把 2、3 两个 diff 依次"打上去"。

**这个模型有一个致命伤，你现在还感受不到，但它是 Git 设计者 Linus Torvalds 最想干掉的：**

> 版本历史越靠后，要"还原"一次提交的成本越高。而且一旦中间某个 diff 损坏，后面所有版本都拼不出来。

---

## 0.2 Git 的答案：不存差异，存快照

2005 年，Linus Torvalds 在 Linux 内核社区用了几年的 BitKeeper（一个商业版本控制工具）因为授权问题被收回，Linux 内核开发**一夜之间没了版本控制工具**。

Linus 的脾气是出了名的——他不打算"凑合用一个现成的"（SVN 那种慢，他看不上），于是他花了大约一周，写了一个新的。这就是 Git。

他写 Git 的时候，脑子里最清楚的一件事是：**内核这种项目，有几万个文件、几十万次提交、几千个开发者同时在改，任何"慢"都是不可接受的。**

而"差异存储"的还原成本，恰恰是"越到后面越慢"。所以 Linus 换了一个完全相反的思路：

**每次 `commit`，把整个项目的完整状态照一张"快照"存下来，而不是存"这次改了什么"。**

用一张图感受一下差别：

```
差异存储（SVN 思路）：
  rev1 ──diff──> rev2 ──diff──> rev3
  要 rev3，得从 rev1 一路打补丁

快照存储（Git 思路）：
  rev1 = 整个目录的照片 A
  rev2 = 整个目录的照片 B   （独立、完整的一张）
  rev3 = 整个目录的照片 C
  要 rev3，直接取照片 C 就行
```

你心里肯定冒出一个反问：**"每次存一整份，那存储空间不得爆炸？"**

这就是 Git 设计里第二聪明的地方。先记住这个结论：

> **Git 的快照不是"每次复制整个项目"，而是"内容寻址"——同一个文件内容，只存一份，大家通过哈希值共享引用它。**

后面 0.4 会展开。现在先看第三件事，也是 Linus 最得意的地方。

---

## 0.3 三棵树：工作区 / 暂存区 / 版本库

假设你已经 `git init` 了一个仓库，建了一个文件 `a.txt`。Git 眼里，你的项目分三个"地方"：

| 名字 | 是什么 | 类比 |
|---|---|---|
| **工作区（working tree）** | 你正在编辑的、看得见的文件 | 你的桌面 |
| **暂存区（index / staging area）** | 你"挑选"了准备提交的内容 | 待发货的打包箱 |
| **版本库（repository）** | `commit` 之后的历史快照 | 已经存档的仓库 |

为什么中间要夹一个"暂存区"？直接"工作区 → 版本库"两步不就行了吗？

**因为 Linus 想要"精确控制你提交什么"。**

一个真实场景：你同时改了 3 个文件——`bug 修复`、`一个半成品的新功能`、`随手改的配置`。这三样**不该塞进同一个 commit**。

有了暂存区，你可以：

```
先 git add  bug修复文件      → 只把"bug 修复"挑进打包箱
再 git add  配置文件          → 也挑进来
（那个半成品功能，故意不 add，留在工作区）
然后 git commit              → 这次提交里，干干净净只有 bug 修复 + 配置
```

**暂存区让你能把"混乱的工作区"整理成"语义清晰的提交"。** 这是 Git 和"自动同步网盘"最大的区别之一——网盘不管语义，Git 逼你（也帮你）讲清楚每次改动的意图。

> 一句话记住它：工作区是你随便造的地方，暂存区是你"挑货"的地方，版本库是"已存档"的地方。三棵树，就是 Git 给你上的一道"想清楚再提交"的闸门。

## 0.4 内容寻址：一切皆对象，一切靠哈希

现在揭开 0.2 留下的悬念：**快照是怎么做到"不爆炸"的？**

Git 把仓库里的一切——文件内容、目录结构、提交信息——都存成一个**对象（object）**。对象分四种：

| 类型 | 存什么 | 类比 |
|---|---|---|
| **blob** | 一个文件的**完整内容** | 一个文件 |
| **tree** | 一个目录的清单（文件名 + 指向 blob/tree 的哈希） | 一个文件夹 |
| **commit** | 一次提交（作者、时间、提交说明、指向 tree 的哈希、指向父 commit 的哈希） | 一个快照节点 |
| **tag** | 一个带说明的指针（通常是给 commit 起个正式名字） | 里程碑标签 |

关键在于：**每个对象的名字，是它内容的 SHA-1 哈希**。

这意味着什么？**同样的内容，哈希一样，就只存一份。**

你改了一个文件里的一行，整个项目照了张新快照——但**没改的那些文件，内容没变，哈希没变，Git 根本不用再存一遍**，新快照里的 tree 直接引用旧 blob 就行。

所以：

> **Git 的"快照"是廉价的。** 它看着像"每次存整份"，实际是"没变的东西只存一次，变了的东西才新增一份"。
> 差异存储是"空间省、时间贵"；Git 是"空间略贵（可压缩）、时间极省"。

而"内容寻址"还送了你两个意外的好处：

1. **内容相同的文件自动去重**——两个文件内容一模一样，不管叫什么名字、放哪，底层就一个 blob。
2. **你几乎不可能"静默损坏"一个版本**——因为 commit 的名字就是内容哈希，内容被篡改一字节，哈希就对不上，Git 立刻能发现。

这就是为什么 Git 的自检命令叫 `git fsck`（fsck = file system check），它本质是在校验"这张哈希网还连得上吗"。

## 0.5 分支为什么在 Git 里便宜到像不要钱

有了"内容寻址 + 快照"打底，Git 里另一个反直觉的特性就顺理成章了：**分支极其廉价。**

在 SVN 那种差异存储里，"开分支"差不多等于"复制一份代码目录"，重、慢、吓人，所以大家能不开就不开。

在 Git 里，**"分支"只是一张写着"某个 commit 的哈希"的小纸条**：

```
main  →  "当前最新 commit 的哈希 = a1b2c3..."
feature → "另一个 commit 的哈希 = d4e5f6..."
```

创建一个分支，就是**写一张新纸条**，耗时几乎为零。切换分支，就是把工作区的内容换成那张纸条指向的快照。

所以 Git 社区才流行一句话：**"分支太便宜了，所以你应该为每一个想法开一个分支。"** 这句话的底气，全来自 0.4 那个"一切皆对象"的设计。

> 一句话记住它：在 Git 里，分支不是"复制代码"，只是一张写着 commit 哈希的纸条。它便宜，是因为 commit 本身已经靠哈希串成了一张随时可跳转的网。

## 0.6 Git 明确不负责什么

最后，讲清楚 Git **不是**什么，省得你拿它当别的工具用：

| 它不是 | 原因 | 该用什么 |
|---|---|---|
| **网盘 / 备份工具** | 它存的是"语义化的提交历史"，不是"所有文件的最新一份"。你不 commit，改的东西就只在你工作区，Git 管不着 | 备份用 NAS / 云盘 |
| **文件同步工具** | 它不会自动把你两个设备的文件"拉平"，你得自己 commit + push + pull | Dropbox / Syncthing |
| **部署工具** | `git push` 到 GitHub 只是推到"代码仓库"，不会自动把代码跑到服务器上跑起来 | CI/CD（GitHub Actions 等） |
| **大文件仓库** | 它按"内容快照"存，塞几个 500MB 的视频进去，仓库会飞快膨胀 | Git LFS 或对象存储 |

**Git 真正负责的只有一件事：帮你精确地记录"谁、在什么时候、为什么、把代码改成了什么样"，并且随时能回到任何一个过去的状态。**

它不是万能的，但它把这一件事做到了极致。
