## 一、高频面试题（Q1~Q50）

### 1. TCP 与网络基础（10 题）

**Q1: 从浏览器输入 URL 到页面显示，中间发生了什么？**

**答：** ① DNS 把域名解析成 IP；② TCP 三次握手建立连接（HTTPS 还有 TLS 握手）；③ 发 HTTP 请求；④ 服务器处理返回响应；⑤ 浏览器渲染页面；⑥ 连接可能四次挥手关闭。这是一条"分层递进"的完整链路。

- 关键区分：**DNS（找机器）→ TCP（建连接）→ HTTP（发请求）→ 渲染**
- 加分项：能说出 HTTPS 还要多一步 TLS 握手

**Q2: TCP 三次握手为什么是三次，不是两次或四次？**

**答：** 三次恰好让双方都确认"我的发送 + 你的接收"正常，同时避免失效连接请求浪费资源。两次的话服务器无法确认客户端收到自己的 SYN+ACK；四次没必要，因为第二次把 ACK 和 SYN 合并成了 SYN+ACK。

- 一句话：**三次 = 交换初始序列号 + 双向确认的最小次数**
- 加分项：说出"合并 ACK/SYN"

**Q3: TCP 是怎么保证可靠传输的？**

**答：** 靠四件套：① 序列号（按字节编号）② 确认号（期待的下一个字节）③ 重传（超时重传 + 3 个重复 ack 触发快速重传）④ 校验和（损坏则丢，当丢包处理）。分别对应"不丢、不乱、不重、不损坏"。

- 关键区分：**丢包靠超时/重复 ack，乱序靠序号排序，重复靠序号去重**
- 加分项：说出"累积确认"（ack=N 表示 N 之前全收到）

**Q4: 什么是队头阻塞？HTTP/2 和 HTTP/3 怎么解决？**

**答：** 队头阻塞 = 前面一个慢的堵住后面所有。HTTP/1.1 是应用层队头阻塞（一条连接请求排队）；HTTP/2 用多路复用（帧 + 流 ID）解决应用层；但还跑在 TCP 上，TCP 层队头阻塞（一个包丢卡所有流）还在；HTTP/3 换 QUIC（基于 UDP），流独立，才根治。

- 关键区分：**应用层队头阻塞 vs 传输层队头阻塞，是两层不同的病**
- 加分项：说出"HTTP/3 为什么选 UDP——TCP 在内核，改不动"

**Q5: TCP 和 UDP 的区别？各自适合什么场景？**

**答：** TCP 面向连接（三次握手）、可靠（序列号+重传）、有序、慢；UDP 无连接、不可靠、无顺序保证、快。TCP 适合要求可靠的场景（HTTP、文件、邮件），UDP 适合要求快的场景（实时音视频、游戏、DNS）。QUIC 是在 UDP 上自己实现可靠。

- 一句话：**TCP 可靠慢，UDP 快不可靠，QUIC 在 UDP 上补可靠**
- 加分项：说出"可靠是有代价的（握手延迟、队头阻塞）"

**Q6: 四次挥手为什么是四次？什么是半关闭？**

**答：** TCP 是双向的，两个方向要各自独立关闭，所以四次。半关闭是"一方发了 FIN（我不再发），但还能收对方数据"的状态——`end` 事件和 `close` 事件之间就是半关闭。

- 关键区分：**`end()` 发 FIN，`close` 才是彻底断**
- 加分项：说出"第 2、3 步不能合并是因为服务器可能还有数据要发"

**Q7: 一个 TCP 连接由什么唯一确定？端口的作用是什么？**

**答：** 由四元组 `（源IP，源端口，目标IP，目标端口）` 唯一确定。端口是"程序的门牌号"，把连接精确到机器上的某个程序。服务器端口公开固定，客户端端口内核随机分。

- 关键区分：**IP 定位机器，端口定位程序**
- 加分项：说出客户端也要端口（服务器才知道回给谁）

**Q8: 什么是流量控制和拥塞控制？有什么区别？**

**答：** 流量控制照顾**接收方**（接收方窗口太小，发送方减速），靠滑动窗口实现；拥塞控制照顾**整个网络**（路由器堵了，大家都减速），靠慢启动 + 拥塞避免 + 快速恢复实现。

- 一句话：**流量控制 = 别冲垮接收方，拥塞控制 = 别冲垮网络**
- 加分项：说出"慢启动指数增长，一丢包窗口砍半"

**Q9: 为什么说 TCP 是"字节流"，没有"消息边界"？**

**答：** TCP 只保证字节**有序、完整**，不保证"你 write 几次，对方 data 几次"。3 次 write 可能被对方 1 次 data 读走，也可能分 3 次。要传"一条条消息"，必须自己在应用层定界（`\n` 分隔或长度前缀）。

- 关键区分：**TCP 保证字节序，不保证消息边界**
- 加分项：举出"聊天消息要自己加分隔符"的例子

**Q10: `ECONNREFUSED` 和 `ECONNRESET` 有什么区别？**

**答：** `ECONNREFUSED` 是"连接被拒绝"——端口没人监听（门都没开）；`ECONNRESET` 是"连接被重置"——连接建立后对端崩了或主动发 RST（聊到一半摔电话）。

- 一句话：**REFUSED 是门没开，RESET 是聊到一半摔电话**
- 加分项：说出优雅关闭 `end()`（FIN）vs 暴力关闭 `destroy()`（RST）

### 2. IP 与 DNS（6 题）

**Q11: 公网 IP 和内网 IP 的区别？为什么别人连不进你的本地服务？**

**答：** 公网 IP 全球唯一，内网 IP 局域网内唯一、可重复（`192.168.x.x` 等）。你本机通常只有内网 IP，外网访问不到；而且你访问外网时靠路由器 NAT 把内网 IP 换成公网 IP。所以要对外提供服务，需要公网 IP 或端口映射/内网穿透。

- 关键区分：**内网 IP 出不了公网，NAT 让几十台设备共享一个公网 IP**
- 加分项：说出"`127.0.0.1` 是回环，只能本机访问"

**Q12: 子网掩码是干什么的？怎么判断两台机器是否同一网段？**

**答：** 子网掩码把 IP 切成"网络号 + 主机号"。判断是否同一网段：IP 与掩码按位与得到网络地址，两个网络地址相同就是同一网段，可直连；不同则要经路由器。

- 关键区分：**同一网段直连，跨网段过路由器**
- 加分项：能算出 `192.168.1.10/24` 的网络地址是 `192.168.1.0`

**Q13: DNS 是怎么把域名解析成 IP 的？**

**答：** DNS 是分层结构（根 → 顶级域 → 二级域 → 子域），从右往左逐级查询；加上各级缓存所以快。本机还有 hosts 文件，优先级高于 DNS。

- 关键区分：**分层 + 缓存，hosts 优先级最高**
- 加分项：说出 A 记录查 IPv4、AAAA 查 IPv6、CNAME 是别名

**Q14: `dns.lookup` 和 `dns.resolve4` 有什么区别？**

**答：** `dns.lookup` 走系统解析（先 hosts 再 DNS）；`dns.resolve4` 跳过 hosts 直接问 DNS。改了 hosts 不生效，往往是因为代码用了 `resolve4`。

- 关键区分：**lookup 走 hosts，resolve4 不走**
- 加分项：说出"改 hosts 不生效先查代码用哪个"

**Q15: 什么是默认网关？它的作用是什么？**

**答：** 默认网关（通常是你家路由器）是你机器出网的第一跳。访问本网段之外的目标，数据先发给默认网关，由它转发。排障时按"自己→网关→公网 IP→域名"顺序 ping，能定位问题出在哪一层。

- 关键区分：**本网段直连，跨网段交给网关**
- 加分项：说出"网关同时是 DHCP 服务器和 NAT 设备"

**Q16: 为什么 IPv4 不够用，还要有 IPv6？**

**答：** IPv4 只有 32 位（约 43 亿地址），早用光了。IPv6 用 128 位，地址多到用不完。IPv6 还带来更好的 NAT 体验（每台设备能有公网 IP）、更简洁的头部。过渡难所以现在还是 IPv4 为主。

- 关键区分：**43 亿 vs 2¹²⁸，量级差**
- 加分项：说出 `::1` 是 IPv6 回环地址

### 3. HTTP 报文、方法与状态码（10 题）

**Q17: HTTP 请求报文和响应报文各由哪几部分组成？**

**答：** 请求报文 = 请求行（方法+路径+版本）+ 请求头 + （空行）+ 消息体；响应报文 = 状态行（版本+状态码+短语）+ 响应头 + （空行）+ 消息体。

- 关键区分：**请求行是"方法+路径"，状态行是"版本+状态码"**
- 加分项：说出"头和体之间必须空行，Content-Length 表示体长"

**Q18: GET 和 POST 的区别？**

**答：** 语义上 GET 是"读"、POST 是"写"。数据位置上 GET 放 URL（query string）、POST 放 body。GET 幂等安全，POST 不幂等。URL 长度受限，body 几乎不受限。

- 关键区分：**读 vs 写、URL vs body、幂等 vs 不幂等**
- 加分项：说出"GET 不用 body 是约定，不是强制"

**Q19: 什么是幂等性？哪些方法幂等？为什么它重要？**

**答：** 幂等 = 执行 1 次和 100 次结果一样。GET/PUT/DELETE 幂等，POST 不幂等，PATCH 看情况。幂等性决定"能不能放心重试"——POST 不幂等，重试会导致重复下单。

- 关键区分：**幂等决定重试安全性**
- 加分项：说出"用幂等键解决 POST 重复问题"

**Q20: PUT 和 PATCH 的区别？**

**答：** PUT 是"整体替换"（缺的字段会被删/覆盖），PATCH 是"局部修改"（只改给的字段）。PUT 幂等，PATCH 不一定（`+1` 不幂等，`设为 x` 幂等）。

- 一句话：**PUT 换整个，PATCH 改一部分**
- 加分项：举例 `PUT /users/1` 替换整个用户 vs `PATCH /users/1` 只改名

**Q21: HTTP 状态码怎么分类？说出几个常见的。**

**答：** 百位数定调：2xx 成功（200/201/204）、3xx 重定向（301/302/304）、4xx 客户端错（400/401/403/404）、5xx 服务器错（500/502/503）。

- 口诀：**2 成功、3 重定向、4 客户错、5 服务器错**
- 加分项：说出 304 不是重定向是缓存

**Q22: 301 和 302 的区别？**

**答：** 301 永久重定向（浏览器会缓存，下次直接去新地址），302 临时重定向（浏览器不缓存，下次还来问）。301 用于换域名/永久迁移，302 用于临时跳转（如登录跳转）。

- 一句话：**301 永久，302 临时**
- 加分项：说出重定向靠 `Location` 头指明新地址

**Q23: 401 和 403 的区别？**

**答：** 401 = 没登录（不知道你是谁），403 = 登录了但没权限（知道你是谁但不许看）。一句话：401 是"你是谁？"，403 是"我知道你，但你不许看"。

- 关键区分：**未认证 vs 已认证无权限**
- 加分项：举例"没登录访问个人中心=401，普通用户看管理员后台=403"

**Q24: 500、502、503 的区别？**

**答：** 500 = 服务器自己代码崩了；502 = 上游服务器挂了（网关连不上后端）；503 = 服务过载/维护中（我还活着但不干活）。

- 关键区分：**500 自己崩、502 上游挂、503 自己暂时不干**
- 加分项：举例"Nginx→Node→数据库"链路里各自的错误码

**Q25: Host 头是干什么的？没有它会怎样？**

**答：** Host 头让"一个 IP 跑多个网站"成为可能——服务器靠它判断"你要访问哪个站点"。HTTP/1.1 请求必须带 Host，没有可能返回 400。

- 一句话：**Host 头 = 虚拟主机分发的依据**
- 加分项：说出"同一个 IP 上 Nginx 按 Host 分发到不同网站"

**Q26: HTTP 是无状态的，这对"登录"意味着什么？**

**答：** HTTP 每次请求独立，服务器"忘了"你是谁。所以登录状态要靠额外机制维持——Cookie（浏览器存凭证）+ Session（服务器存数据），每次请求带 Cookie 让服务器认出你。

- 关键区分：**无状态 = 每次请求独立，记忆要靠 Cookie/Session 补**
- 加分项：说出"无状态让服务器能水平扩展"

### 4. HTTPS 与 TLS（6 题）

**Q27: HTTPS 为什么安全？核心思路是什么？**

**答：** HTTPS = HTTP + TLS。TLS 用混合加密——非对称加密安全交换一把对称密钥，之后全程对称加密。同时证书防中间人、数字签名防篡改。

- 一句话：**非对称换对称，之后全程对称**
- 加分项：说出"贵的干一次，便宜的干一万次"

**Q28: 对称加密和非对称加密的区别？**

**答：** 对称加密一把钥匙又锁又开，快，但钥匙分发难；非对称加密一对钥匙（公钥加密私钥解密），解决分发但慢。所以 TLS 混合用。

- 关键区分：**对称快但分发难，非对称慢但分发易**
- 加分项：说出 RSA 比 AES 慢几个数量级

**Q29: 证书是干什么的？没有证书会怎样？**

**答：** 证书是 CA 给公钥的"盖章"，证明"这个公钥真的属于某域名"。没有证书，中间人可以把公钥偷换成自己的，客户端用它加密，中间人解密——加密白费（中间人攻击）。

- 关键区分：**证书解决"公钥身份"问题**
- 加分项：说出"浏览器内置 CA 公钥来验签"

**Q30: TLS 握手在干什么？**

**答：** 协商加密算法 + 交换随机数 + 验证服务器证书，最终产出一把双方共享的对称密钥，之后数据都用它加密。TLS 1.3 把握手压到 1-RTT。

- 一句话：**协商 + 交换 + 验证，产出对称密钥**
- 加分项：说出 TLS 1.3 的 1-RTT 改进

**Q31: 什么是中间人攻击？HTTPS 怎么防？**

**答：** 中间人攻击是攻击者伪装成服务器，把公钥偷换成自己的，从而解密客户端流量。HTTPS 靠证书防——证书由可信 CA 签名，客户端用内置 CA 公钥验签，发现公钥被偷换就报警（`ERR_CERT_AUTHORITY_INVALID`）。

- 关键区分：**防中间人靠证书，不靠加密本身**
- 加分项：说出"自签证书触发警告，恰恰证明证书机制在工作"

**Q32: 数字签名是怎么保证"内容没被篡改"的？**

**答：** 签名 = 用私钥对消息哈希加密；验签 = 用公钥解密并比对哈希。内容改一个字，哈希就变，验签失败。所以篡改能被发现。

- 一句话：**私钥签名、公钥验签，改了必被发现**
- 加分项：说出"签名绑定了内容和私钥"

### 5. 缓存与 Cookie（8 题）

**Q33: 强缓存和协商缓存的区别？**

**答：** 强缓存（`Cache-Control: max-age`）在有效期内**不发请求**直接用本地；协商缓存（`ETag`/`Last-Modified`）要发请求，但可能只回 304 省 body。两者配合：先强缓存，过期再协商。

- 关键区分：**发不发请求是核心区别**
- 加分项：说出 304 响应不带 body

**Q34: `no-cache` 和 `no-store` 的区别？**

**答：** `no-cache` 是"缓存，但每次用前先问服务器"；`no-store` 是"完全不缓存"。很多人以为 `no-cache` 是不缓存，恰恰反了。

- 一句话：**no-cache 每次先问，no-store 压根不存**
- 加分项：说出隐私数据用 `no-store`

**Q35: ETag 和 Last-Modified 的区别？谁更可靠？**

**答：** ETag 是"版本指纹"（内容哈希），精确到内容；Last-Modified 是"最后修改时间"，精确到秒。ETag 更可靠——1 秒内改多次 Last-Modified 检测不到。现代实践优先 ETag。

- 关键区分：**ETag 精确到内容，Last-Modified 精确到秒**
- 加分项：说出"1 秒内改两次文件 Last-Modified 可能失效"

**Q36: Cookie 是怎么让 HTTP 记住登录状态的？**

**答：** HTTP 无状态。登录时服务器 `Set-Cookie` 让浏览器存凭证，之后每次请求浏览器自动带 `Cookie` 头，服务器据此认出用户。一进一出，就是登录状态的基础。

- 一句话：**Set-Cookie 种，Cookie 带，一进一出**
- 加分项：说出"Cookie 存凭证，Session 存数据"

**Q37: Cookie 和 Session 的区别？为什么不能把用户数据放 Cookie？**

**答：** Cookie 存在浏览器，用户能改、能被 XSS 偷，不可信，且约 4KB 限制；Session 存在服务器端，可信。所以 Cookie 只存凭证（session id），数据放 Session。Cookie 是钥匙，Session 是房间。

- 关键区分：**Cookie 不可信 + 有大小限制，所以只存凭证**
- 加分项：说出"Session 放 Redis 能重启不丢、多机共享"

**Q38: Cookie 的三个安全属性是什么？各防什么？**

**答：** `HttpOnly`（JS 读不到，防 XSS 偷凭证）、`Secure`（只在 HTTPS 传，防窃听）、`SameSite`（跨站请求不带，防 CSRF）。

- 一句话：**HttpOnly 防 XSS、Secure 防窃听、SameSite 防 CSRF**
- 加分项：说出 SameSite 的 Strict/Lax/None 三档

**Q39: 什么是同源策略？为什么需要它？**

**答：** 同源 = 协议 + 域名 + 端口全相同。同源策略是浏览器安全铁律——一个网页的 JS 只能访问同源数据，防止恶意网站偷用你已登录的 cookie 发请求。合法跨域用 CORS 头放行。

- 关键区分：**同源策略是浏览器的规则，服务器之间（curl/Node）没有它**
- 加分项：说出 CORS 头 `Access-Control-Allow-Origin`

**Q40: 304 是什么？它和缓存什么关系？**

**答：** 304 Not Modified 不是重定向，是"内容没变，用你本地缓存"。协商缓存时，服务器比对 ETag/Last-Modified，发现没变就回 304（不带 body），客户端继续用本地缓存。

- 一句话：**304 = 没变，用缓存，省 body**
- 加分项：说出"304 是协商缓存的结果，不是错误"

### 6. HTTP/2、HTTP/3 与工程化（10 题）

**Q41: HTTP/1.1 的主要问题是什么？**

**答：** 队头阻塞——一条连接一次只处理一个请求，慢请求堵住后面所有。浏览器靠开多条并行连接缓解，但连接有成本且受限。

- 一句话：**1.1 的问题是请求排队**
- 加分项：说出"大文件卡前面，小文件全等着"

**Q42: HTTP/2 的核心改进是什么？**

**答：** 多路复用（帧 + 流 ID，一条连接并行多个请求）、头部压缩（HPACK）、二进制分帧、服务器推送。核心是解决 HTTP/1.1 的应用层队头阻塞。

- 一句话：**多路复用是头号改进**
- 加分项：说出"HPACK 让重复的头只发一次"

**Q43: HTTP/2 解决了队头阻塞吗？**

**答：** 解决了**应用层**的，没解决**传输层**的。因为所有流还跑在同一条 TCP 连接上，一个包丢了，整条连接的所有流都得等（TCP 按序上交）。

- 关键区分：**应用层 vs 传输层，两层不同的队头阻塞**
- 加分项：说出"弱网下 HTTP/2 的好处大打折扣"

**Q44: HTTP/3 为什么换掉 TCP？QUIC 是什么？**

**答：** 因为 TCP 的队头阻塞根治不了（TCP 在内核，改不动）。QUIC 是基于 UDP 的协议，在用户态自己实现可靠性和"流独立"——一个流丢包不影响别的流。HTTP/3 就跑在 QUIC 上。

- 一句话：**换 UDP，流独立，根治队头阻塞**
- 加分项：说出"QUIC 握手更短，可 0-RTT"

**Q45: QUIC 跑在 UDP 上，UDP 不可靠，那 HTTP/3 怎么保证可靠？**

**答：** UDP 只是"地基"。QUIC 在 UDP 之上**自己实现**了可靠传输——序号、确认、重传、拥塞控制都搬到用户态做。所以 HTTP/3 依然可靠，只是可靠性由 QUIC 而不是 TCP 提供。

- 关键区分：**UDP 不可靠 ≠ QUIC 不可靠**
- 加分项：说出"在用户态实现可靠，升级不用动内核"

**Q46: REST 的核心原则是什么？**

**答：** URL 用名词表示资源，HTTP 动词表示操作，状态码表示结果，无状态。比如 `GET /users`（查）、`POST /users`（建）、`DELETE /users/1`（删）。

- 一句话：**名词定位资源，动词表示操作**
- 加分项：说出"POST 成功 201、DELETE 成功 204、查不到 404"

**Q47: 为什么说 REST 接口要"无状态"？**

**答：** 无状态 = 每个请求带上所有必要信息（如认证 token），服务器不依赖"上次记住了什么"。这样服务器才能水平扩展（任何一台都能处理请求），也更容易测试和缓存。

- 关键区分：**无状态利于水平扩展**
- 加分项：说出"登录状态靠 token/Cookie 传递，不靠服务器记忆"

**Q48: 抓包调试的思路是什么？**

**答：** 别靠猜，靠亲眼看报文。五步：复现问题 → 看请求报文（方法/URL/头/body 对不对）→ 看响应报文（状态码/头/body）→ 按错误码定位（4xx 查自己，5xx 查服务器）→ 修复验证。

- 一句话：**看请求、看响应、按错误码定位**
- 加分项：说出"传输层错误看 err.code，应用层看 statusCode"

**Q49: 一个可调试的服务器，日志里至少要记什么？**

**答：** 方法、URL、状态码、耗时、来源 IP。有了这几样，就能回答"谁在什么时候访问了什么、结果如何、慢不慢"。出错时还要记错误信息/堆栈。

- 关键区分：**日志是排障的"黑匣子"**
- 加分项：说出"包一层 res.end 自动记日志"的技巧

**Q50: 返回 JSON 时最容易漏什么？为什么？**

**答：** 最容易漏 `Content-Type: application/json`。漏了它，客户端不知道 body 是 JSON，`fetch().json()` 可能解析失败或当纯文本处理。所以通常封装一个 `sendJSON` 统一处理状态码 + Content-Type + 序列化。

- 一句话：**JSON 必须带 Content-Type**
- 加分项：说出"204 不能有 body"这个连带坑

## 二、白板手写题（Q51~Q60）

面试官说"来，写一个"的时候，**先讲思路再动手**——这是第一分。

### 1. TCP 与网络（2 题）

**Q51: 手写一个 TCP echo 服务器，客户端发什么回什么，进程自然退出？**

**答：** 核心是 `createServer` + `data` 事件里原样 `write` 回去 + 优雅关闭。

```js
import net from 'node:net';

const server = net.createServer((socket) => {
  socket.on('data', (d) => socket.write(d)); // 原样回
  socket.on('end', () => socket.end());
});

server.listen(0, '127.0.0.1', () => {
  const client = net.createConnection({ host: '127.0.0.1', port: server.address().port }, () => {
    client.write('你好');
    client.end();
  });
  client.on('data', (d) => console.log('回显:', d.toString()));
  client.on('close', () => server.close(() => console.log('退出')));
});
```

- 讲一句：**TCP 是双向流，data 里 write 回去就是 echo**
- 加分：说清"客户端 `end()` 发 FIN，`close` 才彻底断"

**Q52: 手写一个函数，判断两个 IP 是否在同一网段（/24）？**

**答：** 用位运算把 IP 转整数，与掩码按位与，比较网络地址。

```js
function sameSubnet(a, b, prefix = 24) {
  const toInt = (ip) => ip.split('.').reduce((acc, n) => ((acc << 8) >>> 0) + Number(n), 0) >>> 0;
  const mask = (~0 << (32 - prefix)) >>> 0;
  return (toInt(a) & mask) === (toInt(b) & mask);
}
console.log(sameSubnet('192.168.1.10', '192.168.1.20')); // true
console.log(sameSubnet('192.168.1.10', '192.168.2.10')); // false
```

- 讲一句：**同网段 = 网络地址相同 = 可直连**
- 加分：说清掩码是"前 N 位为 1"

### 2. HTTP 服务器（3 题）

**Q53: 手写一个返回 JSON 的 HTTP 服务器，正确处理 Content-Type 和状态码？**

**答：** 三件事：设 `Content-Type: application/json`、设状态码、`JSON.stringify`。

```js
import http from 'node:http';

function sendJSON(res, code, data) {
  res.statusCode = code;
  res.setHeader('Content-Type', 'application/json; charset=utf-8');
  res.end(JSON.stringify(data));
}

http.createServer((req, res) => {
  if (req.url === '/users') sendJSON(res, 200, [{ id: 1, name: '小明' }]);
  else sendJSON(res, 404, { error: 'Not Found' });
}).listen(3000);
```

- 讲一句：**JSON 必须带 Content-Type，封装 sendJSON 统一处理**
- 加分：说清"204 不能有 body"要单独分支

**Q54: 手写一个读取 POST body 的函数，并处理非法 JSON？**

**答：** body 是流式的，要 `data` 累积、`end` 解析，用 Promise 包起来能 `await`。

```js
function readBody(req) {
  return new Promise((resolve, reject) => {
    let b = '';
    req.on('data', (c) => (b += c));
    req.on('end', () => {
      try {
        resolve(b ? JSON.parse(b) : {});
      } catch {
        reject(new Error('非法 JSON'));
      }
    });
  });
}
```

- 讲一句：**body 是流，要 data 累积、end 解析**
- 加分：说清"非法 JSON 要 reject，返回 400"

**Q55: 手写一个带缓存头的接口，支持 ETag 协商？**

**答：** 比对 `If-None-Match` 和 ETag，匹配回 304，否则回 200 + 新 ETag。

```js
const ETAG = '"v1"';
http.createServer((req, res) => {
  if (req.headers['if-none-match'] === ETAG) {
    res.statusCode = 304;
    res.end();
  } else {
    res.setHeader('ETag', ETAG);
    res.setHeader('Cache-Control', 'public, max-age=60');
    res.end('资源内容');
  }
}).listen(3000);
```

- 讲一句：**If-None-Match 匹配 → 304，不匹配 → 200 + 新 ETag**
- 加分：说清"强缓存 + 协商缓存两级配合"

### 3. 机制讲清楚（3 题）

**Q56: 说清楚 TCP 是怎么做到"可靠传输"的？**

**答：** 四件套：① 序列号按字节编号；② 确认号 = 期待的下一个字节；③ 丢包靠超时重传 + 3 个重复 ack 快速重传；④ 乱序靠接收缓冲区按序号排序、重复靠序号去重、损坏靠校验和。核心是"序号 + 确认"这一对数字。

- 关键区分：**丢包/乱序/重复/损坏，各有各的解法**
- 加分：说出"累积确认，ack=N 表示 N 之前全收到"

**Q57: 说清楚 HTTPS 的握手和加密流程？**

**答：** ① 客户端生成对称密钥；② 用服务器公钥加密它发给服务器；③ 服务器私钥解密拿到对称密钥；④ 双方之后用对称密钥加密通信。证书保证"公钥是真的"，签名保证"内容没被篡改"。

- 关键区分：**非对称换对称，之后全程对称**
- 加分：说出"证书防中间人偷换公钥"

**Q58: 说清楚 HTTP/2 的多路复用是怎么实现的？**

**答：** 把每个请求-响应拆成独立的帧，每个请求一个流 ID，同一条连接上不同流的帧交错传输，接收方按流 ID 重组。于是慢请求的帧挡不住快请求的帧。

- 关键区分：**帧 + 流 ID，交错传输**
- 加分：说出"对比 1.1 的串行，2 是并行"

### 4. 综合（2 题）

**Q59: 手写一个完整的 REST 用户接口（增删改查）？**

**答：** 方法 + 路径分发到内存数组操作，POST 建 201、DELETE 删 204、查不到 404。

```js
let users = [{ id: 1, name: '小明' }];

http.createServer(async (req, res) => {
  const { method } = req;
  const [path] = req.url.split('?');

  if (method === 'GET' && path === '/api/users') {
    sendJSON(res, 200, users);
  } else if (method === 'POST' && path === '/api/users') {
    const body = await readBody(req);
    const u = { id: users.length + 1, name: body.name };
    users.push(u);
    sendJSON(res, 201, u);
  } else if (method === 'DELETE' && path.startsWith('/api/users/')) {
    const id = Number(path.split('/')[3]);
    const before = users.length;
    users = users.filter((x) => x.id !== id);
    if (users.length === before) return sendJSON(res, 404, { error: 'Not Found' });
    sendJSON(res, 204, null);
  } else {
    sendJSON(res, 404, { error: 'Not Found' });
  }
}).listen(3000);
```

- 讲一句：**REST = 方法 + 路径 + 状态码三者统一**
- 加分：说清"精确路由放前缀路由前面"

**Q60: 手写一个能记录每个请求日志的服务器（可调试）？**

**答：** 核心是包一层 `res.end`，让日志自动发生；再 try/catch 兜异常。

```js
http.createServer((req, res) => {
  const start = Date.now();
  const ip = req.socket.remoteAddress;

  const originalEnd = res.end;
  res.end = function (...args) {
    console.log(`[${req.method}] ${req.url} -> ${res.statusCode}（${Date.now() - start} ms）来自 ${ip}`);
    originalEnd.apply(res, args);
  };

  try {
    if (req.url === '/500') throw new Error('模拟错误');
    res.end('ok');
  } catch (err) {
    res.statusCode = 500;
    res.end('500 Internal Server Error');
  }
}).listen(3000);
```

- 讲一句：**包一层 res.end 自动记日志，try/catch 兜异常**
- 加分：说清"日志记方法/URL/状态码/耗时/来源 IP"

### 5. 读命令说结果（3 题）

import net from 'node:net';

function toInt(ip) {

console.log((toInt('192.168.1.10') & mask) >>> 0, '→ 转回 IP 是 192.168.1.0');

**Q63: 下面这段代码，第二次请求返回什么状态码？**

const ETAG = '"v1"';
// 第一次：响应 200 + ETag: "v1"
// 第二次：客户端带 If-None-Match: "v1"

## 三、一页速查表

### HTTP 方法速查

| 方法 | 语义 | 幂等 | 成功状态码 |
|---|---|---|---|
| GET | 读 | 是 | 200 |
| POST | 建 | 否 | 201 |
| PUT | 整体改 | 是 | 200 |
| PATCH | 局部改 | 不一定 | 200 |
| DELETE | 删 | 是 | 204 |
| HEAD | 只要头 | 是 | 200 |

### 状态码速查

| 状态码 | 短语 | 一句话 |
|---|---|---|
| 200 | OK | 成功 |
| 201 | Created | 新建成功 |
| 204 | No Content | 成功无内容（DELETE 常用） |
| 301 | Moved Permanently | 永久跳转 |
| 302 | Found | 临时跳转 |
| 304 | Not Modified | 缓存没变 |
| 400 | Bad Request | 请求格式错 |
| 401 | Unauthorized | 没登录 |
| 403 | Forbidden | 没权限 |
| 404 | Not Found | 不存在 |
| 500 | Internal Server Error | 服务器崩 |
| 502 | Bad Gateway | 上游挂 |
| 503 | Service Unavailable | 过载/维护 |

### 真实错误码速查

| 错误码 | 含义 | 触发条件 |
|---|---|---|
| `ECONNREFUSED` | 连接被拒 | 端口没人监听 |
| `ENOTFOUND` | 域名查不到 | 域名不存在/DNS 不通 |
| `ETIMEDOUT` | 连接超时 | 对端不响应/不可达 |
| `ECONNRESET` | 连接被重置 | 对端崩了/发 RST |
| `EADDRINUSE` | 端口被占 | 两个程序监听同端口 |
| `HPE_INVALID_METHOD` | 非法 HTTP 方法 | 发了一段非 HTTP 数据 |

### 缓存头速查

| 头 | 作用 |
|---|---|
| `Cache-Control: max-age=60` | 60 秒强缓存 |
| `Cache-Control: no-cache` | 缓存但每次先问 |
| `Cache-Control: no-store` | 完全不缓存 |
| `ETag` + `If-None-Match` | 内容指纹协商 |
| `Last-Modified` + `If-Modified-Since` | 修改时间协商 |

### Cookie 属性速查

| 属性 | 防什么 |
|---|---|
| `HttpOnly` | XSS 偷 cookie |
| `Secure` | 明文窃听 |
| `SameSite` | CSRF |

### Node 核心 API 速查

| 我想做的事 | 写法 |
|---|---|
| 起 TCP 服务器 | `net.createServer((socket) => {})` |
| 起 TCP 客户端 | `net.createConnection({ host, port })` |
| 起 HTTP 服务器 | `http.createServer((req, res) => {})` |
| 发 HTTP 请求 | `fetch(url)` 或 `http.request(...)` |
| DNS 查询（走 hosts） | `dns.lookup(name)` |
| DNS 查询（跳过 hosts） | `dns.resolve4(name)` |
| 判断 IP 合法 | `net.isIP(str)` |
| 解析 query string | `new URL(req.url, 'http://x').searchParams` |
| 读请求头 | `req.headers['content-type']`（小写） |
| 设响应头 | `res.setHeader('Content-Type', '...')` |
| 读 POST body | `data` 事件累积 + `end` 解析 |

### 分层排障速查

| 现象 | 出在哪层 | 查什么 |
|---|---|---|
| `ECONNREFUSED` | 传输层 | 服务/端口 |
| `ENOTFOUND` | DNS 层 | 域名/DNS |
| HTTP 4xx | 应用层（客户端） | 请求本身 |
| HTTP 5xx | 应用层（服务器） | 服务器日志 |

## 四、面试技巧

### 4.1 不会的时候怎么救场

**核心原则：把"不知道"换成一个有价值的过程。**

- ❌ 别硬编答案。说出一句错的原理，比说"我不确定"伤害大得多。
- ✅ 可以说：**"这个点我记不太准，但我知道它要解决的是 X 问题，能让我说下思路吗？"**
- ✅ 把问题**降维到你会的那一层**：不会答"拥塞控制的具体算法"，就说"我理解它是为了别把网络冲垮，核心是慢启动、一丢包就减速，跟流量控制照顾接收方是两回事"。**用你掌握的等价知识接住问题。**
- ✅ 明说**边界**："这块我目前只到会用，没深入看过实现。"诚实 + 说明掌握程度，好过硬撑。
- ✅ **把追问变成加分**：被问住时反问"您是想确认实现原理，还是想看我能不能用对？"

**三句万能救场句：**

1. "我先说结论，再说为什么，可以吗？"
2. "我没遇到过这个具体场景，我的推理是这样的……"
3. "这个点我回去会补，能说说你们实际是怎么处理的吗？"

### 4.2 可以反问什么

面试的最后环节，**反问的质量常常决定印象分**。按目标挑 2~3 个：

**想了解团队与工程成熟度：**

- 你们现在 HTTP 服务用什么框架？为什么选它？
- 线上怎么监控接口的耗时和错误？有统一的日志/埋点吗？
- 你们的服务是 HTTP/2 还是 HTTP/3？为什么？
- 遇到"连不上""超时"这类问题，你们的排查流程是什么样的？

**想了解技术挑战与成长：**

- 目前你们最头疼的网络/接口问题是什么？
- 最近一次接口性能优化，是为了解决什么瓶颈？
- 新人入职前三个月，通常会遇到什么挑战？

**反向加分项（显示你懂工程）：**

- "你们的接口是怎么做幂等和限流的？"
- "缓存的失效策略是怎么设计的？有没有踩过缓存不一致的坑？"

**别问的：** 薪资细节（留给 HR）、能在官网查到的公开信息、以及"你们用 HTTP 吗"这种能自己判断的。

### 4.3 现场写代码的 5 个习惯

1. **先复述需求 + 确认边界。** "我理解是要一个返回 JSON 的接口，需要处理 404 和错误，对吗？需要缓存吗？"——这一步就能拉开差距。
2. **先讲思路再敲代码。** "我打算用 `http.createServer`，路由按方法+路径分发，JSON 统一用 `sendJSON` 处理……"讲完再动手。
3. **命名要清楚。** `readBody`、`sendJSON`、`handleError`——面试官看的就是这些细节。
4. **主动指出取舍。** "这里我用内存数组当数据库，是为了演示；生产会用真正的数据库。"
5. **写完主动自检。** "这里有个边界：204 不能有 body，所以我单独处理了。"——展示你有"运行时"的意识。

### 4.4 高频陷阱题识别

| 听到这个问法 | 真正考的是什么 |
|---|---|
| "HTTP/2 解决队头阻塞了吗？" | 你知不知道**应用层和传输层是两层**，2 只解决了前者 |
| "HTTPS 是不是把数据都加密了？" | 你知不知道**混合加密**（非对称换对称）和**证书防中间人** |
| "`no-cache` 是不缓存吗？" | 你知不知道 `no-cache` 是"每次先问"，`no-store` 才是不缓存 |
| "401 和 403 有什么区别？" | 你能不能一句话说清"未认证 vs 已认证无权限" |
| "POST 能重试吗？" | 你知不知道**幂等性**决定重试安全性 |
| "TCP 可靠吗？" | 你敢不敢说"可靠是有代价的"（队头阻塞、握手延迟） |
| "为什么别人连不进你本地服务？" | 你知不知道**内网 IP + NAT** |
| "这段代码有什么问题？"（给你一段 `res.end(JSON.stringify(x))`） | 你有没有"运行时"直觉——一眼看出漏了 Content-Type |

**最后一条提醒：** 面试官真正想知道的只有两件事——**你能不能把网络的分层讲清楚**，以及**出问题时你能不能自己定位到哪一层**。所有题目都是这两件事的变体。

> 一句话记住它：**面试考的不是"你知道多少"，而是"你能不能把为什么讲清楚"。**
