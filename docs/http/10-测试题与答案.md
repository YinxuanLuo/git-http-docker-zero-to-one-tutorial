## 第一关 · 概念快问快答（20 题）

判断下面每句话是**对**还是**错**。不要猜，想清楚理由。

1. TCP 是字节流，所以"你 write 几次，对方就 data 几次"是保证的。
2. 端口是一个 0 到 65535 的整数，用来区分同一台机器上的不同程序。
3. 三次握手是为了让双方交换初始序列号，并各自确认"我能发、你能收"。
4. TCP 的序列号是按"包"编号的，不是按"字节"编号的。
5. TCP 通过"序列号 + 确认号 + 超时重传"，在连接存续期间保证字节不丢、不乱、不重复。
6. 断开连接是四次挥手，因为 TCP 是双向的，两个方向要各自独立关闭。
7. `127.0.0.1` 和 `localhost` 永远指向同一个东西，可以随意混用。
8. 一个 IP 地址配合子网掩码，能算出它所属的网络地址。
9. `dns.lookup` 会先查 hosts 文件，`dns.resolve4` 跳过 hosts 直接问 DNS 服务器。
10. HTTP 是应用层协议，跑在 TCP 之上，报文是纯文本的。
11. HTTP 请求报文由"请求行 + 请求头 + 消息体"组成，头和体之间用空行分隔。
12. GET 请求可以携带消息体，而且这是推荐做法。
13. POST 请求是幂等的，可以放心地自动重试。
14. 状态码 304 表示"资源永久重定向到新地址"。
15. 状态码 401 表示"没登录"，403 表示"登录了但没权限"。
16. HTTPS 是用对称加密来交换非对称密钥，之后全程用非对称加密传数据。
17. TLS 证书的作用是证明"这个公钥真的属于目标服务器"，从而防中间人偷换公钥。
18. `Cache-Control: no-cache` 表示"完全不缓存"。
19. Cookie 的 `HttpOnly` 属性让 JavaScript 读不到它，能防止 XSS 偷走登录凭证。
20. HTTP/2 的多路复用彻底解决了 TCP 层的队头阻塞。

## 第三关 · 改错（10 题）

每题给你一段**能跑出问题**的代码。先别看修正，自己找。

### 3.1 返回 JSON 忘了设 Content-Type

**问题代码：**

```js
const server = http.createServer((req, res) => {
  res.end(JSON.stringify({ ok: true }));
});
```

**症状**：客户端 `fetch().json()` 解析失败，或拿到的是纯文本。

**为什么**：`res.end(JSON.stringify(...))` 只发了 body，没设 `Content-Type`，客户端不知道 body 是 JSON。

**修正代码：**

```js
const server = http.createServer((req, res) => {
  res.setHeader('Content-Type', 'application/json; charset=utf-8');
  res.end(JSON.stringify({ ok: true }));
});
```

### 3.2 路由没去掉 query string

**问题代码：**

```js
const server = http.createServer((req, res) => {
  if (req.url === '/api/users') {
    res.end('用户列表');
  }
});
// 客户端请求 /api/users?page=2
```

**症状**：请求 `/api/users?page=2` 时，`req.url === '/api/users'` 为 false，路由匹配不上。

**为什么**：`req.url` 包含 query string（`/api/users?page=2`），直接用 `===` 比较路径会失败。

**修正代码：**

```js
const server = http.createServer((req, res) => {
  const [path] = req.url.split('?'); // 去掉 query string
  if (path === '/api/users') {
    res.end('用户列表');
  }
});
```

### 3.3 204 响应写了 body

**问题代码：**

```js
res.statusCode = 204;
res.end('删除了'); // ❌ 204 不能有 body
```

**症状**：客户端行为异常，可能报错。

**为什么**：`204 No Content` 表示"成功但没有内容"，不该有 body。

**修正代码：**

```js
res.statusCode = 204;
res.end(); // 什么都不写
```

### 3.4 解析 body 没捕获非法 JSON

**问题代码：**

```js
const server = http.createServer(async (req, res) => {
  let b = '';
  req.on('data', (c) => (b += c));
  req.on('end', () => {
    const body = JSON.parse(b); // ❌ 非法 JSON 直接抛错
    res.end('ok');
  });
});
```

**症状**：客户端发了非法 JSON（比如 `{a:}`），服务器直接抛 `SyntaxError`，进程可能崩。

**为什么**：`JSON.parse` 遇到非法 JSON 会抛异常，没人捕获。

**修正代码：**

```js
req.on('end', () => {
  try {
    const body = b ? JSON.parse(b) : {};
    res.end('ok');
  } catch {
    res.statusCode = 400;
    res.end('非法 JSON');
  }
});
```

### 3.5 静态文件有路径穿越漏洞

**问题代码：**

```js
import fs from 'node:fs/promises';

const server = http.createServer(async (req, res) => {
  const content = await fs.readFile('/www' + req.url, 'utf8');
  res.end(content);
});
```

**症状**：请求 `/../../etc/passwd` 能读到系统任意文件。

**为什么**：`req.url` 里的 `../` 没被过滤，路径能逃出 `/www` 根目录。

**修正代码：**

```js
import path from 'node:path';

const safe = path.normalize('/www' + req.url);
if (!safe.startsWith('/www/')) {
  res.statusCode = 403;
  return res.end('Forbidden');
}
const content = await fs.readFile(safe, 'utf8');
res.end(content);
```

### 3.6 服务器只听 IPv4，客户端用 localhost 连

**问题代码：**

```js
// 服务器只监听 IPv4
server.listen(3000, '127.0.0.1');

// 客户端用 localhost 连（可能解析成 ::1）
const client = net.createConnection({ host: 'localhost', port: 3000 });
```

**症状**：连不上，报 `ECONNREFUSED`。

**为什么**：`localhost` 可能解析成 IPv6 的 `::1`，而服务器只听 IPv4 的 `127.0.0.1`，两边对不上。

**修正代码：**

```js
// 方案一：两端用同一个地址
server.listen(3000, '127.0.0.1');
net.createConnection({ host: '127.0.0.1', port: 3000 });

// 方案二：服务器监听所有网卡
server.listen(3000); // 不指定 host，IPv4/IPv6 都监听
```

### 3.7 用 GET 做删除操作

**问题代码：**

```js
// 删除用户用 GET，还带 id
http.get('http://example.com/api/deleteUser?id=1');
```

**症状**：数据可能被误删（爬虫、预加载、链接预览都可能触发这个 GET）。

**为什么**：GET 的语义是"安全、幂等"的读操作，不该有副作用。用 GET 做删除，任何"获取"这个 URL 的东西都可能误触发删除。

**修正代码：**

```js
// 删除用 DELETE 动词
http.request({
  host: 'example.com',
  path: '/api/users/1',
  method: 'DELETE',
}).end();
```

### 3.8 混淆 401 和 403

**问题代码：**

```js
// 用户没登录访问，却返回 403
res.statusCode = 403; // ❌ 应该 401
res.end('请先登录');
```

**症状**：语义错误——403 是"认证了但没权限"，而这里用户根本没认证。

**为什么**：401 = "没登录（不知道你是谁）"，403 = "登录了但没权限"。没登录应该 401。

**修正代码：**

```js
res.statusCode = 401; // 未认证
res.setHeader('WWW-Authenticate', 'Bearer');
res.end('请先登录');
```

### 3.9 异步处理函数没捕获异常

**问题代码：**

```js
const server = http.createServer(async (req, res) => {
  const data = await db.query(); // ❌ 可能抛错
  res.end(JSON.stringify(data));
});
```

**症状**：`db.query()` 抛错时，请求卡死，甚至进程崩溃。

**为什么**：`async` 函数里的异常没人 `catch`，变成未处理的 Promise 拒绝。

**修正代码：**

```js
const server = http.createServer(async (req, res) => {
  try {
    const data = await db.query();
    res.end(JSON.stringify(data));
  } catch (err) {
    console.error('服务器错误:', err);
    res.statusCode = 500;
    res.end('500 Internal Server Error');
  }
});
```

### 3.10 以为 write 几次对方就 data 几次

**问题代码：**

```js
// 客户端
client.write('第一句');
client.write('第二句');
client.write('第三句');

// 服务器（错误假设：每次 write 对应一次 data）
socket.on('data', (d) => {
  // 假设 d 一定是一整条消息，直接处理
  handleMessage(d.toString());
});
```

**症状**：`handleMessage` 可能拿到半条消息，或三条拼在一起的消息。

**为什么**：TCP 是字节流，没有消息边界，3 次 write 可能被合并成 1 次 data。

**修正代码：**

```js
// 方案：自己定界（比如每条消息用 \n 分隔）
let buffer = '';
socket.on('data', (d) => {
  buffer += d.toString();
  let idx;
  while ((idx = buffer.indexOf('\n')) !== -1) {
    const msg = buffer.slice(0, idx);
    buffer = buffer.slice(idx + 1);
    handleMessage(msg); // 拿到完整的一条
  }
});
```

### 第 1 题

**Q：从浏览器输入 URL 到页面显示，中间发生了什么？**

**A：** 先 DNS 把域名解析成 IP；然后 TCP 三次握手建立连接（HTTPS 还有 TLS 握手）；再发 HTTP 请求；服务器处理并返回响应；浏览器渲染；最后可能四次挥手断开。这是一个典型的"分层递进"过程。

> **面试官想听到的要点：** 不要只说"发请求收响应"，要能说出 **DNS → TCP（→TLS）→ HTTP → 渲染** 这条链路，体现你有分层意识。

### 第 2 题

**Q：TCP 三次握手为什么是三次，不是两次或四次？**

**A：** 三次恰好能让双方都确认"自己的发送 + 对方的接收"正常，同时避免失效的连接请求浪费资源。两次的话，服务器没法确认客户端收到了自己的 SYN+ACK；四次没必要，因为第二次握手把 ACK 和 SYN 合并了。

> **面试官想听到的要点：** 说出"双向确认"和"合并 ACK/SYN"两点，而不是只背"三次"。

### 第 3 题

**Q：TCP 是怎么保证可靠传输的？**

**A：** 靠"序列号 + 确认号 + 重传 + 校验"：序列号按字节编号，确认号表示"期待的下一个字节"；丢包靠超时重传和快速重传发现；乱序靠接收缓冲区按序号排序；重复靠序号去重；损坏靠校验和。

> **面试官想听到的要点：** 能说出四件套，并分别对应"不丢、不乱、不重、不损坏"。

### 第 4 题

**Q：什么是队头阻塞？HTTP/2 和 HTTP/3 是怎么解决的？**

**A：** 队头阻塞是"前面一个慢的堵住后面所有"。HTTP/1.1 是应用层队头阻塞（一条连接请求排队）；HTTP/2 用多路复用解决了应用层的；但仍跑在 TCP 上，TCP 层队头阻塞还在（一个包丢卡所有流）；HTTP/3 换 QUIC（基于 UDP），流独立，才根治。

> **面试官想听到的要点：** 能分清"应用层队头阻塞"和"传输层队头阻塞"两层，并对应到 HTTP/2 和 HTTP/3 的解法。

### 第 5 题

**Q：HTTPS 为什么安全？核心思路是什么？**

**A：** HTTPS = HTTP + TLS。TLS 用混合加密——非对称加密安全交换一把对称密钥，之后全程对称加密。同时证书解决"公钥是不是真的"（防中间人），数字签名解决"内容没被篡改"。

> **面试官想听到的要点：** "混合加密"这个词，以及证书防中间人、签名防篡改。

### 第 6 题

**Q：证书是干什么的？没有证书会怎样？**

**A：** 证书是 CA 给公钥的"盖章"，证明"这个公钥真的属于 example.com"。没有证书，中间人可以把自己的公钥冒充成服务器的公钥，客户端用它加密会话密钥，中间人就能解密——整个加密白费（中间人攻击）。

> **面试官想听到的要点：** 说清"证书解决公钥身份问题"，能描述中间人攻击的完整流程。

### 第 7 题

**Q：GET 和 POST 的区别？**

**A：** 语义上 GET 是"读"、POST 是"写"。数据位置上，GET 放 URL（query string）、POST 放 body。GET 幂等、安全；POST 不幂等。长度上 URL 有限制、body 几乎没有。

> **面试官想听到的要点：** 不要只说"GET 参数在 URL"，要说出**语义**（读 vs 写）和**幂等性**。

### 第 8 题

**Q：什么是幂等性？哪些 HTTP 方法是幂等的？**

**A：** 幂等 = 执行 1 次和 100 次结果一样。GET、PUT、DELETE 幂等；POST 不幂等；PATCH 看情况。幂等性决定"这个请求能不能放心重试"。

> **面试官想听到的要点：** 能举出"POST 重试导致重复下单"这个具体例子。

### 第 9 题

**Q：401 和 403 的区别？**

**A：** 401 = 没登录（不知道你是谁），403 = 登录了但没权限（知道你是谁但不许看）。一句话：401 是"你是谁？"，403 是"我知道你，但你不许看"。

> **面试官想听到的要点：** 这个区分一句话说清，还能举例（没登录 vs 普通用户看管理员后台）。

### 第 10 题

**Q：强缓存和协商缓存的区别？**

**A：** 强缓存（`Cache-Control: max-age`）在有效期内**不发请求**直接用本地；协商缓存（`ETag`/`Last-Modified`）要发请求，但可能只回 304 省 body。两者配合：先强缓存，过期再协商。

> **面试官想听到的要点：** 分清"发不发请求"是核心区别，以及 304 的意义（省 body）。

### 第 11 题

**Q：Cookie 和 Session 的区别？为什么不能把用户数据直接放 Cookie？**

**A：** Cookie 存在浏览器，用户能改、能被 XSS 偷，不可信，且大小受限；Session 存在服务器端，可信。所以 Cookie 只存凭证（session id），真正的数据放 Session。Cookie 是钥匙，Session 是房间。

> **面试官想听到的要点：** 说出"Cookie 不可信 + 大小限制"这个因果，而不是只说"Session 在服务器"。

### 第 12 题

**Q：同源策略是什么？为什么需要它？**

**A：** 同源 = 协议 + 域名 + 端口全相同。同源策略是浏览器的安全铁律——一个网页的 JS 只能访问同源的数据，防止恶意网站偷用你已登录的 cookie 发请求（CSRF 等）。合法跨域用 CORS 头放行。

> **面试官想听到的要点：** 能说出"防恶意网站偷 cookie 发请求"这个动机，以及 CORS 是合法放行手段。

### 第 13 题

**Q：DNS 是怎么把域名解析成 IP 的？**

**A：** DNS 是分层结构（根 → 顶级域 → 二级域 → 子域），从右往左逐级查询；加上各级缓存所以很快。本机还有 hosts 文件，优先级高于 DNS。

> **面试官想听到的要点：** 说出"分层 + 缓存"，以及 hosts 优先级高于 DNS。

### 第 14 题

**Q：TCP 和 UDP 的区别？**

**A：** TCP 面向连接（三次握手）、可靠（序列号+重传）、有序、慢；UDP 无连接、不可靠、无顺序保证、快。TCP 适合要求可靠的场景（HTTP、文件传输），UDP 适合要求快的场景（实时音视频、游戏），QUIC 在 UDP 上自己实现可靠。

> **面试官想听到的要点：** 说出"可靠 vs 快"的本质取舍，以及 QUIC 是"在 UDP 上补可靠"。

### 第 15 题

**Q：HTTP/1.1、HTTP/2、HTTP/3 的核心区别？**

**A：** 1.1 文本、请求排队（队头阻塞）；2 二进制 + 多路复用 + 头部压缩，解决了应用层队头阻塞；3 换 QUIC（基于 UDP），流独立，解决了 TCP 层队头阻塞。主线就是一路跟"阻塞"作斗争。

> **面试官想听到的要点：** 用"队头阻塞"这条主线串起三代，而不是孤立罗列特性。

## 第五关 · 项目实战（5 题）

这 5 题要真的动手写，写完用 `node` 跑通。参考答案可在 `examples/http/` 下找到对应示例。

### 第 1 题 · Echo 服务器

**需求：**

1. 用 `node:net` 起一个 TCP 服务器。
2. 客户端发什么，服务器原样回什么（echo）。
3. 客户端发完 `end()`，进程自然退出。

**参考答案：** [`examples/http/01-TCP连接与封装.mjs`](../../examples/http/01-TCP连接与封装.mjs)（改一下数据处理逻辑即可）

```bash
node examples/http/01-TCP连接与封装.mjs
```

**自测要点：** 客户端发三段数据，看服务器是否把三段都回显了。

### 第 2 题 · 带缓存头的 HTTP 服务器

**需求：**

1. 用 `node:http` 起服务。
2. 一个接口返回 `Cache-Control: max-age=60` + `ETag`。
3. 客户端带 `If-None-Match` 访问时，匹配则返回 304，不匹配返回 200。

**参考答案：** [`examples/http/06-缓存与Cookie.mjs`](../../examples/http/06-缓存与Cookie.mjs)

```bash
node examples/http/06-缓存与Cookie.mjs
```

**自测要点：** 第一次 200 + ETag，第二次带 If-None-Match 得到 304。

### 第 3 题 · REST 用户接口

**需求：**

1. 实现用户资源的增删改查（GET/POST/PUT/DELETE）。
2. POST 成功返回 201，DELETE 成功返回 204，查不到返回 404。
3. 所有 JSON 响应都要带 `Content-Type: application/json`。

**参考答案：** [`examples/http/09-完整HTTP服务器.mjs`](../../examples/http/09-完整HTTP服务器.mjs)

```bash
node examples/http/09-完整HTTP服务器.mjs
```

**自测要点：** 逐个验证 200/201/204/404 状态码是否正确。

### 第 4 题 · 可调试服务器

**需求：**

1. 每个请求都打印日志：方法、URL、状态码、耗时、来源 IP。
2. 出错时捕获异常，返回 500，不崩进程。
3. 处理 `clientError`（客户端协议错误）返回 400。

**参考答案：** [`examples/http/08-可调试服务器.mjs`](../../examples/http/08-可调试服务器.mjs)

```bash
node examples/http/08-可调试服务器.mjs
```

**自测要点：** 访问 `/404`、`/500`、发一段垃圾数据，看日志是否完整。

### 第 5 题 · 综合：路由 + 静态文件 + JSON

**需求：**

1. 实现 REST 路由（用户资源）。
2. 实现静态文件服务（读磁盘文件返回）。
3. 实现 404 兜底。
4. 写完用内置 `fetch` 自测所有端点。

**参考答案：** [`examples/http/09-完整HTTP服务器.mjs`](../../examples/http/09-完整HTTP服务器.mjs)

```bash
node examples/http/09-完整HTTP服务器.mjs
```

**自测要点：** 覆盖正常路径 + 边界（删完再查返回 404、不存在的路径返回 404）。
