# 第 03 章 · IP 与 DNS：数据是怎么找到那台机器的

> 前两章你学会了"建连接、可靠传输"。但有个更基本的问题没解决：**你在浏览器敲 `example.com`，全世界几亿台机器，TCP 到底去连哪一台？**
>
> 本章你需要记住的就一件事：**IP 地址负责"定位机器"（靠子网+路由找到它在哪），DNS 负责"把名字翻译成 IP"（靠 hosts 文件和 DNS 服务器）。TCP 连接的是 IP，不是域名。**
>
> 这一条想清楚了，你就能解释"为什么换个 Wi-Fi 网页打不开""为什么内网机器能互相直连""为什么改了 hosts 就能劫持域名"这些日常现象。

---

## 03.1 从"找到一台机器"说起

**先说结论**：TCP 连接需要的是一个 **IP 地址**，不是域名。你在浏览器敲 `example.com`，背后要先经历一步"**域名 → IP**"的翻译，然后 TCP 才拿着这个 IP 去连。

把整个链路串起来看：

```text
你敲下 example.com
   ↓
① 翻译：DNS 把 example.com 查成 IP（比如 93.184.216.34）
   ↓
② 定位：拿着 IP，网络层靠"子网 + 路由"找到这台机器
   ↓
③ 连接：TCP 跟这个 IP 建连接、传数据（第 02 章讲的）
```

这一章讲 ① 和 ②。它们回答的是同一个问题：**"那一台机器，到底怎么被找到的？"** 拆成两问：

- 机器有了 IP，**怎么知道它在世界哪个位置？** → 子网、路由
- 机器只有名字（域名），**怎么知道它的 IP 是多少？** → DNS、hosts

先给一个直觉：**IP 地址像"省市区街道门牌"，DNS 像"通讯录查姓名得到地址"。** 你要寄快递（发数据），得先查通讯录（DNS）拿到门牌（IP），再让快递系统按门牌找路（路由）。

> 一句话记住它：TCP 连的是 IP 不是域名；先 DNS 把名字翻译成 IP，再靠子网+路由找到机器——这是"找到那台机器"的两步。

---

## 03.2 IP 地址：互联网的"门牌号"

**先说结论**：IP 地址是一串**唯一标识一台机器（准确说是网卡）**的数字。现在互联网主流用的是 IPv4（32 位），正在逐步过渡到 IPv6（128 位）。

**IPv4 长什么样？** 32 个二进制位，为了好读，写成 4 段十进制，每段 0~255，中间用点隔开：

```text
192.168.1.10
 192     168      1      10
11000000 10101000 00000001 00001010   ← 底层其实是这 32 个 bit
```

**32 位最多能表示多少个地址？** 2³² ≈ 43 亿。听起来很多，但**远远不够**——全世界的手机、电脑、服务器、物联网设备，早就把 43 亿用光了。这就是为什么要有 IPv6（03.8 节），以及为什么你家的设备常常用的是"内网地址"（03.4 节）。

**你的机器有哪些 IP？** 用 `node:os` 看一眼（配套示例 `examples/http/03-DNS与IP.mjs` 也涉及）：

```js
import os from 'node:os';

const nets = os.networkInterfaces();
for (const [name, addrs] of Object.entries(nets)) {
  for (const a of addrs) {
    console.log(name, a.family, a.address);
  }
}
```

你会看到一堆 IP，其中最重要的两个概念：

| 地址 | 含义 |
|---|---|
| `127.0.0.1` / `::1` | **回环地址**：就是"自己"，数据不出网卡 |
| `192.168.x.x` / `10.x.x.x` | **内网地址**：只在局域网里有效，出不了互联网 |

**判断一个 IP 是不是合法，`node:net` 有现成的：**

```js
import net from 'node:net';

console.log(net.isIP('127.0.0.1'));   // 4（IPv4）
console.log(net.isIP('::1'));         // 6（IPv6）
console.log(net.isIP('999.1.1.1'));   // 0（不是合法 IP）
```

> 一句话记住它：IPv4 是 32 位、写成 4 段十进制的门牌号；43 亿个地址不够用，所以有内网地址和 IPv6。

## 03.3 公网 IP 和内网 IP：为什么你家的 IP 和别人家"重复"

**先说结论**：你在家里电脑上看到的 `192.168.1.10`，全国可能有几千万台机器都在用同一个。它们不是冲突，而是因为这些是**内网地址**，只在各自的小局域网里有效，出了门就无效。

**这就要先理解"公网 IP"和"内网 IP"的区别：**

| | 公网 IP | 内网 IP |
|---|---|---|
| 唯一性 | 全球唯一 | 局域网内唯一，不同局域网可重复 |
| 谁能直接连 | 全世界都能连 | 只有同一局域网内能连 |
| 谁分配 | 运营商 | 你家的路由器 |
| 典型地址 | 各种 | `192.168.x.x`、`10.x.x.x`、`172.16~31.x.x` |

**你上网的真实路径是这样的：**

```text
你的电脑（192.168.1.10，内网）
   ↓ 发给路由器
你家的路由器（有 1 个公网 IP，比如 1.2.3.4）
   ↓ 路由器做"地址转换"（NAT）
真正的互联网（看到的都是路由器的公网 IP）
```

**关键机制叫 NAT（网络地址转换）**：路由器把你的内网 IP 换成它的公网 IP，再发出去；收到回复后，再换回你的内网 IP 发给你。**于是全世界只看到"你家路由器"这一个公网 IP，你家几十台设备都藏在它后面。**

**这解释了三个日常现象：**

1. **为什么别人的电脑连不进你本地起的小服务器？** 因为你只有内网 IP，外面的人访问不到。要对外提供服务，得做"端口映射"（在路由器上把公网端口转发到你的内网机器）。
2. **为什么公司几十台电脑共用一个出口？** 因为它们共享公司的公网 IP，靠 NAT 区分。
3. **为什么 IPv4 不够用还能撑到现在？** 正是因为 NAT 让大量设备共享一个公网 IP，大大缓解了地址枯竭。

> 一句话记住它：内网 IP 可重复、出不了门；公网 IP 全球唯一；NAT 让几十台内网设备共享一个公网 IP——这就是"别人连不进你本地服务"的原因。

## 03.4 子网掩码：同一网段 vs 跨网段

**先说结论**：一个 IP 地址由两部分组成——**网络号**（表示"你在哪个网段"）和**主机号**（表示"你是这个网段里的哪台"）。子网掩码就是用来**切分**这两部分的。

**为什么要分网段？** 想象全世界几十亿台机器都要互相找到，如果一台一台地找，累死了。于是把机器**按地理位置/组织分组**，先找到"你在哪个组（网段）"，再到组里找你。就像寄快递先按"省"找，再按"市"找，最后按"门牌"找。

**子网掩码怎么切分？** 它也是一串 32 位，`1` 的位置表示"网络号"，`0` 的位置表示"主机号"。

最常见的 `/24` 掩码：

```text
IP 地址:   192.168.1.10
子网掩码:  255.255.255.0    （/24 表示前 24 位是 1）

192.168.1   → 网络号（前 3 段）
        10  → 主机号（最后 1 段）
```

**"同一网段"意味着什么？** 两台机器，如果**网络号相同**，就在同一网段，可以直接通信（不用经过路由器）；网络号不同，就要**经过路由器转发**。

**怎么判断两台机器是否同一网段？** 用 IP 和掩码做**按位与（AND）**，得到"网络地址"，比较两个网络地址是否相同。

配套示例 `examples/http/03-DNS与IP.mjs` 里有这个计算（用位运算亲手算）：

```js
function ipToInt(ip) {
  return ip.split('.').reduce((acc, n) => ((acc << 8) >>> 0) + Number(n), 0) >>> 0;
}
function intToIp(n) {
  return [24, 16, 8, 0].map((s) => (n >>> s) & 0xff).join('.');
}

const ip = '192.168.1.10';
const prefix = 24;                                  // /24
const mask = (~0 << (32 - prefix)) >>> 0;           // 255.255.255.0
const netAddr = intToIp(ipToInt(ip) & mask);        // 按位与

console.log(netAddr); // 192.168.1.0
```

实测输出：

```text
IP       : 192.168.1.10
掩码 /24 : 255.255.255.0 (255.255.255.0)
网络地址 : 192.168.1.0 (同网段的机器可直连，跨网段要经路由器)
```

**一个真实到实用的结论**：`192.168.1.10/24` 和 `192.168.1.20/24`，网络地址都是 `192.168.1.0`，**同一网段**，可以直连；而 `192.168.1.10/24` 和 `192.168.2.10/24`，网络地址不同，**跨网段**，要经路由器。

> 一句话记住它：IP = 网络号 + 主机号，子网掩码负责切分；网络号相同就同一网段可直连，不同就要过路由器。

## 03.5 路由的直觉：数据怎么跨越千山万水

**先说结论**：数据从你到对方，不是"一条直线直达"，而是**一站一站地接力**——每经过一台路由器，就往"更接近目标"的方向转发一次。路由就是"每台路由器怎么决定下一跳发给谁"。

**先破除一个直觉错误**：数据包上没有"完整路线图"。它只知道**目标 IP**，然后每到一个路由器，路由器查自己的"路由表"，决定"下一跳"该发给谁。这个过程叫**逐跳转发（hop-by-hop）**。

画个图：

```text
你的电脑 → 家里的路由器 → 运营商路由器 → 骨干网路由器 → … → 对方路由器 → 对方服务器
          (跳1)          (跳2)          (跳3)      …        (跳n-1)      (跳n)
```

**路由器和路由表**：每台路由器维护一张"路由表"，记录"**要到达 XX 网段，该从哪个口出去、下一跳是谁**"。路由器收到包，看目标 IP，查表，转发。仅此而已。

**你本地也有路由表**。Windows 上跑 `route print`，Linux/Mac 上跑 `route -n`，能看到。你发的每个包，先查本机路由表，决定是"直接发给同网段机器"还是"发给默认网关"。

**为什么要有路由协议？** 路由表不是天生就有的，是路由器之间通过**路由协议**（如 OSPF、BGP）互相交换信息，动态学习出来的。BGP 就是"互联网的导航系统"——全世界各大运营商的路由器，靠它互相通告"我这边能到哪些网段"。

**对你写代码的意义**：你几乎不用管路由（那是网络基础设施的事），但理解"逐跳转发"能帮你解释一个常见现象——**`traceroute` 能列出数据经过的每一跳**。想看你的数据经过了哪些路由器：

```bash
# Windows
tracert example.com

# Linux / Mac
traceroute example.com
```

输出会是一行一行的"第几跳 + 路由器 IP + 耗时"，让你直观看到"数据不是直线，是一站一站跳过去的"。

> 一句话记住它：数据靠"逐跳转发"——每台路由器查路由表决定下一跳，一站一站接力到目标；你只管写目标 IP，路线由路由器动态算。

## 03.6 默认网关：出网的那扇门

**先说结论**：你的机器要访问"本网段之外"的地址，会把数据发给**默认网关（default gateway）**——通常就是你家的路由器。它是你机器通往外部世界的唯一出口。

**回到 03.4 的判断**：如果目标 IP 和你**同一网段**，直接发（不经过路由器）；如果**不同网段**，就把包交给默认网关，让网关去转发。

**你家的路由器就是默认网关**。它有三个身份：

| 身份 | 说明 |
|---|---|
| 你的默认网关 | 你机器出网的第一跳 |
| DHCP 服务器 | 给你的设备自动分配内网 IP |
| NAT 设备 | 把你的内网 IP 换成公网 IP（03.3 节） |

**看自己机器的网关**：

```bash
# Windows
ipconfig

# Linux / Mac
route -n        # 或 ip route
```

找 `Default Gateway` 那一行，通常是 `192.168.1.1` 或 `192.168.0.1` 之类——那就是你家的路由器。

**一个真实的排障经验**：网络不通时，按这个顺序判断，能快速定位到哪一层出问题：

```text
1. ping 127.0.0.1     → 通了说明本机网卡/协议栈正常
2. ping 自己的内网 IP  → 通了说明网卡正常
3. ping 默认网关       → 通了说明到路由器的路正常
4. ping 8.8.8.8       → 通了说明能出网（到公网正常）
5. ping example.com   → 不通但第 4 步通，说明 DNS 出问题了
```

这五步，每一步都对应一个层，是第 08 章"抓包调试"的前置心法。

> 一句话记住它：默认网关（路由器）是你出网的第一跳；本网段直连，跨网段交给网关——排障时按"自己→网关→公网 IP→域名"的顺序 ping，能定位问题出在哪一层。

## 03.7 IPv6：为什么需要它

**先说结论**：IPv4 只有 43 亿个地址，早就用光了。IPv6 把地址从 32 位扩到 **128 位**，地址多到"给地球上每一粒沙子分配一个都用不完"。

**128 位有多大？** 2¹²⁸ ≈ 3.4 × 10³⁸，一个天文数字。写成 8 组十六进制：

```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

太长不好读，可以缩写（连续的 0 用 `::` 表示）：

```text
2001:db8::ff00:42:8329
```

**第 01 章已经见过 IPv6 了**：`localhost` 解析出来可能就是这个：

```text
::1   ← IPv6 的回环地址（等价于 IPv4 的 127.0.0.1）
```

**IPv6 的三大改进：**

| 改进 | 说明 |
|---|---|
| 地址几乎无限 | 128 位，彻底解决地址枯竭 |
| 不再需要 NAT | 每台设备都能有公网 IP，点对点直连 |
| 更简洁的头部 | 路由器处理更快 |

**那为什么现在还是 IPv4 为主？** 因为过渡难——全世界的路由器、软件、运营商都要升级，是个几十年的渐进过程。你现在写代码，大多数时候还在跟 IPv4 打交道，但**要知道 IPv6 的存在，尤其是 `localhost` 可能解析成 `::1` 这个坑**（第 01 章讲过）。

> 一句话记住它：IPv4 地址不够用，IPv6 用 128 位彻底解决；日常仍以 IPv4 为主，但记住 `::1` 是 IPv6 的回环地址。

## 03.8 DNS：把域名翻译成 IP

**先说结论**：DNS（Domain Name System）是一套**分布式的"电话本"**，把好记的域名（`example.com`）翻译成机器要用的 IP（`93.184.216.34`）。它是分布式的，因为全世界域名太多，一台服务器存不下。

**为什么需要 DNS？** 因为人记不住 IP（谁能背下 `93.184.216.34` 是哪个网站？），但机器又只认 IP。所以需要一层"翻译"。

**DNS 是怎么查的？** 它有一套**分层**的结构（又是一次分层思想）：

```text
根域名服务器（.）
   │
   ├─ 顶级域（.com、.org、.cn、.io …）
   │
   └─ 二级域（example.com、google.com …）
        │
        └─ 子域（www.example.com、api.example.com …）
```

查 `www.example.com` 的过程是**从右往左、从上到下**：

```text
1. 问根服务器：".com 的服务器是谁？"
2. 问 .com 服务器："example.com 的服务器是谁？"
3. 问 example.com 服务器："www.example.com 的 IP 是多少？"
4. 拿到 IP，返回
```

**但这套流程实际很少完整走**，因为**缓存**无处不在：你本机缓存、路由器缓存、运营商 DNS 缓存……大多数查询在缓存就命中了，不用跑到根服务器。

**DNS 记录类型**，最常见的几个：

| 类型 | 查什么 |
|---|---|
| `A` | 域名 → IPv4 地址 |
| `AAAA` | 域名 → IPv6 地址 |
| `CNAME` | 别名 → 真名（`www` 常是某域名的别名） |
| `MX` | 邮件服务器 |
| `TXT` | 任意文本（常用于域名验证） |

**用 `node:dns` 亲手查**（配套示例 `examples/http/03-DNS与IP.mjs`）：

```js
import dns from 'node:dns/promises';

const r1 = await dns.lookup('localhost');
console.log(r1); // { address: '::1', family: 6 }

const r2 = await dns.resolve4('example.com');
console.log(r2); // 一个 IPv4 地址数组，比如 ['93.184.216.34']
```

> 一句话记住它：DNS 是分层的"电话本"，把域名翻译成 IP；有缓存所以快；A 记录查 IPv4，AAAA 查 IPv6，CNAME 是别名。

## 03.9 hosts 文件：你本地的"DNS"

**先说结论**：你的机器上有个 **hosts 文件**，优先级**高于** DNS。改它，就能让某个域名指向你指定的 IP——这就是"本地劫持域名"的原理。

**hosts 文件在哪：**

| 系统 | 路径 |
|---|---|
| Windows | `C:\Windows\System32\drivers\etc\hosts` |
| Linux / Mac | `/etc/hosts` |

**它长什么样**（每行一条"IP 域名"）：

```text
127.0.0.1       localhost
192.168.1.100   my-test-server.com
```

**解析顺序是这样的：**

```text
查域名
  ↓
① 先查 hosts 文件 → 有就返回，不问了
  ↓
② 没有 → 查 DNS
```

**所以你在 hosts 里写一行 `127.0.0.1 example.com`，再访问 example.com，就会连到你自己**（前提是 127.0.0.1 上有服务）。这就是很多开发场景的惯用技巧——把测试域名指到本地。

**`dns.lookup` 和 `dns.resolve4` 的区别，正好在这里体现**（第 03.8 的代码已经埋了伏笔）：

| 方法 | 走 hosts 吗 | 走 DNS 吗 | 说明 |
|---|---|---|---|
| `dns.lookup` | **走** | 走（hosts 没命中时） | 模拟"浏览器解析"的完整流程 |
| `dns.resolve4` | 不走 | 走 | 跳过 hosts，直接问 DNS |

**为什么这个区别重要？** 因为很多程序内部用 `dns.lookup`（等价于系统的 `getaddrinfo`），所以**改了 hosts 对它们生效**；而直接用 `resolve4` 的，则绕过了 hosts。调试时如果你改了 hosts 却发现不生效，可能就是代码用了 `resolve4`。

**hosts 的常见用途：**

1. 开发时把测试域名指到本地。
2. 屏蔽某些网站（把它的域名指到 `127.0.0.1` 或 `0.0.0.0`）。
3. 临时让一个域名指向测试服务器。

> 一句话记住它：hosts 文件是本地的"DNS"，优先级高于 DNS；`dns.lookup` 走 hosts，`dns.resolve4` 不走——改 hosts 不生效时，先查代码用的是哪个。

## 03.10 真实报错：ENOTFOUND 和 ECONNREFUSED

**先说结论**：DNS 解析失败，Node 会抛 `ENOTFOUND`；解析成功但连不上，抛 `ECONNREFUSED`。这两个错误经常一起出现，但**原因完全不同**，必须分清。

配套示例 `examples/http/10-真实报错码.mjs` 里有完整的复现。这里先看 DNS 的：

```js
import dns from 'node:dns/promises';

try {
  await dns.lookup('this-domain-does-not-exist-9f3a2b.example');
} catch (e) {
  console.log(e.code); // ENOTFOUND
}
```

实测输出：

```text
错误码: ENOTFOUND
原文  : getaddrinfo ENOTFOUND this-domain-does-not-exist-9f3a2b.example
```

**两个错误的对比，一定要刻进脑子：**

| 错误码 | 真实含义 | 触发条件 | 出在哪一层 |
|---|---|---|---|
| `ENOTFOUND` | 域名查不到 | 域名不存在 / DNS 服务器连不上 | **DNS（应用层）** |
| `ECONNREFUSED` | 连接被拒绝 | IP 是通的，但那个端口没人监听 | **TCP（传输层）** |
| `ETIMEDOUT` | 连接超时 | IP 通但对方不响应 / 网络不可达 | **TCP/IP** |

**排障时的关键判断**：

- 拿到 `ENOTFOUND` → 说明**名字没翻译成 IP**，查域名写错没、DNS 通不通、hosts 有没有干扰。
- 拿到 `ECONNREFUSED` → 说明**翻译成功了**（拿到了 IP），但**那台机器那个端口没服务**，查服务起没起、端口对不对。

**这个区分能帮你少走很多弯路**：很多新手一看到"连不上"就以为 DNS 坏了，其实如果是 `ECONNREFUSED`，DNS 是好的，是服务没起。

> 一句话记住它：`ENOTFOUND` 是"名字查不到"（DNS 层），`ECONNREFUSED` 是"端口没人听"（TCP 层）；看到错误码先分清楚是哪一层，再对症排查。

## 03.11 本章常见坑速查

| 坑 | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 改了 hosts 不生效 | 还是连到旧地址 | 代码用了 `resolve4`，绕过了 hosts | 用 `dns.lookup`，或确认程序走系统解析 |
| `localhost` 解析成 `::1` | IPv4 服务连不上 | `localhost` 优先解析成 IPv6 | 服务端监听所有网卡，或明确用 `127.0.0.1` |
| 内网 IP 想让外网访问 | 外网连不进 | 内网 IP 出不了公网 | 路由器做端口映射 / 用公网 IP |
| 以为 IP 能精确定位"人" | 定位偏差很大 | IP 只能定位到城市/运营商级，不是门牌级 | 别指望 IP 精准定位 |
| 用 IP 直接连网站 | 连不上或连错 | 一个 IP 上可能跑很多网站（虚拟主机），需要 Host 头 | 用域名，HTTP 请求里带上 Host 头（第 04 章） |
| 分不清 `ENOTFOUND` 和 `ECONNREFUSED` | 排错方向跑偏 | 两者出在不同层 | `ENOTFOUND` 查域名，`ECONNREFUSED` 查端口 |
| 误以为"IP 变了就找不到" | —— | IP 是临时的、可变的 | 用域名（DNS 帮你屏蔽 IP 变化） |

## 03.12 本章小结

- **TCP 连的是 IP，不是域名**；找到机器分两步：DNS 翻译名字、IP+路由定位机器。
- **IPv4** 32 位、4 段十进制；43 亿不够用，靠 NAT（内网共享公网 IP）续命。
- **公网 IP 全球唯一，内网 IP 可重复**；内网设备靠路由器 NAT 出网。
- **子网掩码**把 IP 切成网络号 + 主机号；网络号相同可直连，不同要过路由器。
- **路由是逐跳转发**：每台路由器查路由表决定下一跳，一站一站到目标。
- **默认网关**（路由器）是出网第一跳；排障按"自己→网关→公网 IP→域名"顺序 ping。
- **IPv6** 用 128 位彻底解决地址枯竭；`::1` 是回环地址。
- **DNS** 是分层电话本，把域名翻译成 IP；A 查 IPv4、AAAA 查 IPv6、CNAME 是别名。
- **hosts 文件**优先级高于 DNS；`dns.lookup` 走 hosts，`resolve4` 不走。
- **`ENOTFOUND`** 是"名字查不到"（DNS），**`ECONNREFUSED`** 是"端口没人听"（TCP）。

## 03.13 动手练习

**1. 判断：`192.168.1.10/24` 和 `192.168.1.200/24` 是否在同一网段？`192.168.1.10/24` 和 `192.168.2.10/24` 呢？**

<details><summary>参考答案</summary>

- `192.168.1.10/24` 和 `192.168.1.200/24`：网络号都是 `192.168.1`，**同一网段**，可直连。
- `192.168.1.10/24` 和 `192.168.2.10/24`：网络号分别是 `192.168.1` 和 `192.168.2`，**不同网段**，要经路由器。

判断方法：IP 和掩码做按位与，算出网络地址，比较网络地址是否相同。

</details>

**2. `dns.lookup` 和 `dns.resolve4` 有什么区别？什么时候这个区别会坑你？**

<details><summary>参考答案</summary>

`dns.lookup` 走**系统解析**（先 hosts 文件，再 DNS）；`dns.resolve4` 跳过 hosts，**直接问 DNS**。

坑在你改了 hosts 文件想让域名指到本地，但程序用的是 `resolve4`，就会绕过 hosts、不生效。调试时改 hosts 不生效，先确认代码走的是哪个。

</details>

**3. 你本机起了个服务监听 `127.0.0.1:3000`，朋友在外地能访问吗？为什么？怎么做才能让别人访问？**

<details><summary>参考答案</summary>

不能。`127.0.0.1` 是回环地址，只能本机访问；而且你的机器通常只有内网 IP，外网访问不到。

要让别人访问，需要：把服务监听在所有网卡（`0.0.0.0`），并且有公网 IP（或通过内网穿透/端口映射把公网流量转到你的内网机器）。

</details>

**4. 下面代码运行后，`e.code` 是什么？为什么？**

```js
import net from 'node:net';

const s = net.connect({ host: '127.0.0.1', port: 1 });
s.on('error', (e) => console.log(e.code));
```

<details><summary>参考答案</summary>

大概率是 `ECONNREFUSED`。因为 `127.0.0.1:1` 几乎没人监听，内核直接回 RST，连接被拒绝。

注意区分：这里 IP 是通的本机地址，问题出在"端口没人听"，所以是 `ECONNREFUSED`（TCP 层），不是 `ENOTFOUND`（DNS 层）。

</details>

**5. 为什么说"IP 是定位到机器，端口是定位到程序"？一个 IP 上能跑多个网站吗？**

<details><summary>参考答案</summary>

IP 定位到"哪台机器"，端口定位到"机器上的哪个程序"。一台机器（一个 IP）上可以跑多个网站——它们共享同一个 80 端口，但通过 HTTP 请求里的 **Host 头**（告诉服务器"我要访问哪个域名"）来区分。这就是"虚拟主机"的原理，第 04 章会详细讲 Host 头。

</details>
