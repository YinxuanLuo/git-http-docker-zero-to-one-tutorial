## 一、高频面试题（Q1~Q50）

### 1. 基础概念（8 题）

**Q1: 镜像、容器、仓库分别是什么？什么关系？**

**答：** 镜像是只读的构建产物（类），容器是镜像运行起来的实例（实例），仓库是存放镜像的远端 registry。`docker pull` 从仓库拉镜像，`docker run` 把镜像跑成容器，`docker push` 推回仓库。

- 关键区分：**镜像只读、容器可销毁、仓库在远端**
- 类比 npm：registry / 包 / 运行中的程序

**Q2: 容器和虚拟机有什么区别？为什么容器更快？**

**答：** 虚拟机虚拟的是**硬件**（每个虚机一个完整 Guest OS），容器虚拟的是**操作系统视图**（复用宿主内核，用 namespace + cgroup 隔离用户空间）。所以容器启动 = 启动一个被圈起来的进程（毫秒级），虚拟机要启动一整个 OS（几十秒）。代价是容器隔离性弱、且必须与宿主同内核。

- 关键区分：**虚拟硬件 vs 虚拟 OS 视图**
- 加分：说出 namespace（隔离"看什么"）+ cgroup（限制"用多少"）

**Q3: Docker 的架构是怎样的？client 和 daemon 什么关系？**

**答：** 三层：client（`docker` 命令行，把命令翻译成 REST 请求）、daemon（`dockerd` 后台进程，真正干活）、registry（存镜像的远端）。client 和 daemon 可以不在同一台机器（`-H` 远程连接）。daemon 是单点，它挂了所有命令报 `Cannot connect to the Docker daemon`。

- 关键区分：**client 传话、daemon 干活、registry 存镜像**

**Q4: Docker 是容器技术的发明者吗？底层依赖什么？**

**答：** 不是。Docker 2013 年出现，本质是把 Linux 早就有的 namespace + cgroup + UnionFS **包装成好用的工具**，是容器技术的普及者。底层技术早已存在于内核。

- 加分：知道 namespace/cgroup/UnionFS 三件套

**Q5: 为什么说 Docker 解决的是"环境一致性"而不是"打包代码"？**

**答：** 因为程序依赖的从来不只是代码，还有 Node 版本、依赖版本、系统库、glibc 等一整套环境。Docker 把"代码 + 环境"在构建时打包成不可变镜像，运行时只是点亮它，于是"我这儿能跑，你那儿一定能跑"。这是对"works on my machine"诅咒的根治。

- 关键词：**不可变镜像 + 构建时固化环境**

**Q6: 镜像的"不可变"带来什么好处？**

**答：** 三个好处：1) 环境一致（镜像一样，环境就一样）；2) 回滚简单（旧镜像还在，指回去就行）；3) 可复现 bug（拉下镜像，bug 原样复现）。

- 关键因果：**不可变 → 环境一致 + 秒级回滚**

**Q7: Windows/Mac 上的 Docker 和 Linux 上的 Docker 有区别吗？**

**答：** 有。Linux 容器必须跑在 Linux 内核上，所以 Windows/Mac 的 Docker Desktop 其实是先起一个**轻量 Linux 虚拟机**，容器跑在那个虚拟机里。这解释了为什么 Windows/Mac 上 Docker 占内存更大。

- 关键词：**容器共享宿主内核，跨系统靠虚拟机**

**Q8: `docker run` 背后发生了什么？**

**答：** `docker run` = `docker create`（创建容器）+ `docker start`（启动）+ `docker attach`（前台附着）。找不到镜像时自动 pull。理解拆解后就知道：run 的参数在创建时定死，不能改，只能重建。

- 关键区分：**run 是快捷方式，create/start 是分步操作**

### 2. 镜像与分层（8 题）

**Q9: 镜像是由什么组成的？**

**答：** 一串**只读层**从下往上叠起来，每层记录"相对上一层的文件系统变化"。底层是基础系统，顶层是应用。合起来看是一个完整文件系统，物理上分层存储、共享、复用。

- 关键词：**只读层 + 叠加**

**Q10: 为什么要"分层"而不是"一个大文件"？**

**答：** 因为层能表达**增量**。多个镜像共享同一底层，只下载/存一份；升级只传变化的那一层；构建时改代码只需重建最上面几层。这是"差分"思想，和 Git 的快照 + 内容寻址同源。

- 关键区分：**层 = 增量，大文件 = 全量**

**Q11: 什么是"内容寻址"？它带来什么？**

**答：** 每层的身份是 sha256(内容)，内容一样 digest 就一样。带来：1) 层可复用（共享底层只存一份）；2) 完整性校验（内容被改 digest 就变）；3) 缓存判断（digest 没变就命中缓存）。

- 关键因果：**内容一样 → digest 一样 → 可复用/可校验/可缓存**

**Q12: OverlayFS 是怎么把多层"叠"成一个文件系统的？**

**答：** OverlayFS 把多个只读层 + 一个可写层叠成一个视图：**读的时候自上而下找第一个命中**（上层覆盖下层），**写的时候永远写进最上面的可写层**（删除用 whiteout 标记遮住，不真删）。容器启动时在最上面加一层可写层，所以容器里的写不影响镜像。

- 关键词：**上层覆盖下层 + 写进可写层**

**Q13: `docker pull` 输出里的 `Already exists` 是什么意思？**

**答：** 表示那一层本地已经有了（可能来自其它镜像共享），直接复用、不重复下载。这是分层 + 内容寻址带来的"下载省"的体现。`Pull complete` 才是"这层刚下好"。

- 关键词：**层共享，已有即跳过**

**Q14: `latest` 标签代表什么？生产能用吗？**

**答：** `latest` 只是"没写 tag 时的默认值"，**不代表最新版本**，它指向哪个镜像取决于维护者给谁打了这个标签，且会被移动。生产不能用（版本不确定、不可复现），要写死明确版本（`nginx:1.27`）甚至 digest。

- 关键区分：**latest = 默认 tag ≠ 最新**

**Q15: 镜像的 digest 和 tag 有什么区别？**

**答：** tag 是**可移动**的标签（`latest`、`1.27` 可以重新指向别的镜像）；digest 是**内容指纹**（sha256），焊死内容，不可变。用 digest 引用是绝对精确的（`nginx@sha256:6139...`）。

- 关键区分：**tag 可移动，digest 焊死**

**Q16: 构建缓存什么时候失效？**

**答：** 每条指令算一个缓存键（指令内容 + 上一层 digest），从**第一条变化的指令**开始，它和它后面的所有层都要重建，前面的继续命中缓存。`COPY` 的缓存键看**文件内容**（不看指令文本），内容一变这层就失效。

- 推论：**贵且不常变的指令排最前**（依赖安装靠前，源码 COPY 靠后）

### 3. 容器与 Dockerfile（10 题）

**Q17: `docker ps` 和 `docker ps -a` 的区别？**

**答：** `docker ps` 只显示**运行中**的容器；`-a`（all）显示所有状态（含 exited）。`-q` 只要 id（脚本用）。STATUS 列是关键：`Up` 在跑、`Exited (码)` 停了。

- 高频坑：**新手总以为容器丢了，其实只是没加 -a**

**Q18: `docker stop` 和 `docker kill` 的区别？**

**答：** `stop` 发 SIGTERM（给进程 10 秒优雅退出，超时才强杀），`kill` 发 SIGKILL（立即死）。所以退出码 143 = 优雅退出，137 = 强杀。能 stop 就别 kill。

- 关键区分：**温柔劝退 vs 一枪崩了**

**Q19: `docker exec` 和 `docker run` 的区别？**

**答：** `exec` 在**已运行**的容器里跑命令（`docker exec -it 容器 bash` 进入），`run` 基于镜像**新建并启动**一个容器。`exit` 只退出 exec 的进程，不影响容器本身。

- 高频坑：**想"进去"却用 run，等于又起一个新容器**

**Q20: `-d` 和 `-it` 分别是什么？能一起用吗？**

**答：** `-d`（detach）后台运行、命令秒回；`-it` = `-i`（开 stdin，能输入）+ `-t`（开 TTY，有提示符），用于交互。两者一般不同时用：后台服务用 `-d`，交互 shell 用 `-it`。

- 关键区分：**-d 后台、-it 交互**

**Q21: Dockerfile 里 `RUN` 和 `CMD` 的区别？**

**答：** `RUN` 是**构建时**执行（`docker build` 阶段），结果固化成一层；`CMD` 是**运行时**执行（容器启动命令）。用 `RUN node server.js` 想启动服务是错的——那是 build 阶段执行。

- 关键区分：**RUN 构建时、CMD 运行时**

**Q22: `CMD` 和 `ENTRYPOINT` 的区别？怎么组合？**

**答：** `CMD` 是默认命令，可被 `docker run` 末尾参数**整体覆盖**；`ENTRYPOINT` 是固定命令，末尾参数**不覆盖它、只变成它的参数**。组合：ENTRYPOINT 定命令 + CMD 定默认参数。都推荐 exec 形式。

- 记忆：**CMD 软默认，ENTRYPOINT 硬命令**

**Q23: exec 形式和 shell 形式有什么区别？**

**答：** exec 形式（`CMD ["node", "server.js"]`）直接以 node 为主进程（PID 1），SIGTERM 信号直达；shell 形式（`CMD node server.js`）会包一层 `/bin/sh -c`，主进程是 sh，信号被 sh 挡住，优雅退出失效。

- 关键区分：**exec 形式主进程就是目标程序，信号直达**

**Q24: `COPY` 和 `ADD` 的区别？**

**答：** `ADD` 多两个能力：自动解压 tar、支持 URL。但这俩容易惹祸（行为隐形、引入不确定性），官方建议能用 COPY 就用 COPY。另注意尾斜杠：`COPY src/` 复制内容，`COPY src` 复制目录本身。

- 关键词：**默认 COPY**

**Q25: `EXPOSE` 会开放端口吗？**

**答：** 不会。`EXPOSE` 只是**声明**端口（写进镜像元数据），不真正开放。真正开放靠 `docker run -p 宿主:容器`，或 `-P` 映射所有 EXPOSE 端口到随机宿主端口。

- 关键区分：**声明 vs 真正开放**

**Q26: 为什么要把依赖清单的 COPY 放在源码 COPY 之前？**

**答：** 因为 `COPY` 的缓存键看文件内容。`package.json` 不常变，先 COPY 它再 `RUN npm install`，install 这层能长期命中缓存；而源码常变，放后面。反过来（先 `COPY . .` 再 install），每次改代码都重装依赖。

- 核心原则：**贵且不常变的排最前**

### 4. 网络与卷（8 题）

**Q27: 端口映射 `-p` 怎么理解？**

**答：** `-p 宿主端口:容器端口`，左边是宿主机（外面访问的），右边是容器（应用真正监听的）。`127.0.0.1:8080:80` 只绑本机（更安全）。写反是高频错误。

- 口诀：**左宿主机右容器**

**Q28: bridge、host、none 三种网络模式的区别？**

**答：** `bridge`（默认）：独立私有 IP + NAT，靠端口映射对外；`host`：共享宿主网络栈，无独立 IP、无需端口映射、性能高但无隔离；`none`：彻底断网（只有 lo），用于纯计算/高隔离。

- 关键区分：**隔离程度 bridge > host > none 是反的（host 无隔离）**

**Q29: 容器之间怎么通信？默认 bridge 能用容器名吗？**

**答：** 自定义网络里容器直接用**容器名**互访（内置 DNS 解析，地址 127.0.0.11）。默认 bridge 是旧实现，没有 DNS，只能靠 IP。所以多容器互联用自定义网络，`--link` 是更早的过时机制。

- 关键词：**容器名互访靠内置 DNS，IP 会变名字不变**

**Q30: 容器的数据会丢吗？怎么持久化？**

**答：** 容器可写层随容器删除而销毁，数据默认会丢。持久化：**volume**（Docker 管理，`-v 卷名:路径`，生产存数据）和 **bind mount**（挂宿主绝对路径，`-v /host:容器`，开发热更）。`docker rm` 不删卷，命名卷数据在容器删后仍在。

- 关键区分：**volume 生产、bind mount 开发**

**Q31: 匿名卷和命名卷的区别？**

**答：** `-v /data`（只写容器路径）是匿名卷（Docker 起随机名，难管理，删容器后变孤儿堆积）；`-v pgdata:/data` 是命名卷（有名字好管理）。日常用命名卷，孤儿卷 `docker volume prune` 清理。

- 关键词：**命名卷推荐，匿名卷会堆积**

**Q32: `docker rm` 会删卷吗？`docker rm -v` 呢？**

**答：** `docker rm` 不删卷（匿名卷和命名卷都不删）。`docker rm -v` 只删它挂的**匿名卷**，命名卷仍不删。命名卷要 `docker volume rm 卷名`。

- 关键区分：**rm 不删卷，rm -v 只删匿名卷**

**Q33: 端口占用报什么错？**

**答：** `Bind for 0.0.0.0:8080 failed: port is already allocated`，意思是宿主机端口被占。换端口，或先找出占用者。报错后可能有 Created 残留容器，记得 rm。

- 关键词：**port is already allocated = 宿主端口被占**

**Q34: 多个容器怎么共享数据？**

**答：** 一个卷可以挂到多个容器（`-v shared:/data`），一个写、多个读。但多个容器同时写同一文件会有竞态（和多个进程写同一文件一样），所以适合"一写多读"。

- 关键词：**共享卷，一写多读**

### 5. Compose 与工程化（8 题）

**Q35: compose 解决什么问题？**

**答：** 把"一堆 docker run + 网络 + 卷"声明成一个 YAML 文件，`docker compose up` 一键起整套、`down` 一键清。本质是 docker run 参数的**声明式**写法。

- 关键词：**声明式编排，up/down 管理整套**

**Q36: `depends_on` 能保证服务就绪吗？**

**答：** 不能。`depends_on` 只保证启动**顺序**，不保证被依赖服务已**就绪**（如数据库初始化完成）。要等就绪：服务加 healthcheck，`depends_on` 用 `condition: service_healthy`；简单场景 `restart: on-failure` 重试。

- 关键区分：**顺序 ≠ 就绪**

**Q37: `docker compose down` 和 `down -v` 的区别？**

**答：** `down` 停服务、删容器、删自动建的网络，**保留卷和镜像**；`down -v` 额外**删卷**（数据没了）。除非确定清库，别用 `-v`。

- 关键词：**down -v 会删数据**

**Q38: 什么是多阶段构建？解决什么问题？**

**答：** 一个 Dockerfile 多个 `FROM`，每个 FROM 开一个阶段，最终镜像只含最后一个阶段。构建工具（编译器、dev 依赖）只在第一阶段，`COPY --from` 把产物拷到运行阶段。解决"构建工具和运行时不分"导致的镜像臃肿 + 攻击面大。

- 关键词：**阶段一构建、阶段二只拷产物**

**Q39: 怎么减小镜像体积？**

**答：** 三板斧：1) 换 alpine/slim 基础镜像（立减 80%）；2) 多阶段构建（工具链不进镜像）；3) `.dockerignore` 减小构建上下文。外加：合并 RUN、只装生产依赖、装完即清理。

- 关键词：**alpine + 多阶段 + .dockerignore**

**Q40: `.dockerignore` 有什么用？**

**答：** 像 `.gitignore`，告诉 Docker 构建时别把这些文件放进构建上下文。排除 node_modules/.git/.env，能让上下文从几百 MB 降到几 MB（build 快），并防止敏感信息（.env 密码）被打进镜像。

- 关键词：**减小上下文 + 防泄漏**

**Q41: 容器默认以什么用户运行？怎么改？**

**答：** 默认 **root**。root 权限大，被攻破后危害大。改法：先 root 做完安装，最后 `USER` 切到非 root 用户（最小权限原则）。

- 关键词：**最小权限，先装后切**

**Q42: 为什么日志要往 stdout 打？**

**答：** `docker logs` 读的是容器 stdout/stderr，日志收集系统（ELK、Loki、云日志）也靠收集 stdout。写文件的话，日志系统收不到，`docker logs` 也看不到。这是容器化应用的规范姿势。

- 关键词：**日志 = stdout/stderr**

### 6. 安全与运维（8 题）

**Q43: Docker 安全主要关注哪几点？**

**答：** 三条主线：1) 最小权限（非 root、少端口、少卷）；2) 镜像扫描（`docker scout`/trivy 找漏洞）；3) 可信镜像源（官方 + 固定版本 + digest）。外加：密钥不进镜像、定期更新基础镜像。

- 关键词：**最小权限 + 扫描 + 可信源**

**Q44: 为什么不能用 `latest` 部署？**

**答：** `latest` 会漂移（指向哪个版本不确定），导致"这次部署和上次不一样"、不可复现、无法回滚。生产要固定版本号（`nginx:1.27`）甚至 digest。

- 关键词：**版本漂移 = 不可复现**

**Q45: 什么是健康检查（healthcheck）？**

**答：** 定义"怎么探测一个容器是否健康"（跑一条命令，退出码 0 算健康）。参数：`test`（探测命令）、`interval`（间隔）、`timeout`（超时）、`retries`（失败几次算不健康）。配合 `depends_on: condition: service_healthy` 让服务等依赖就绪。

- 关键词：**探测 + 就绪门控**

**Q46: 容器退出码 137 和 143 分别是什么？**

**答：** 137 = 被 SIGKILL 强杀（`docker kill`、OOM 被杀），143 = 收到 SIGTERM 优雅退出。`docker stop` 发 SIGTERM（143），`kill` 发 SIGKILL（137）。

- 关键区分：**143 优雅、137 强杀**

**Q47: 什么是重启策略（restart）？有哪些？**

**答：** 容器意外退出时自动重启的规则：`no`（默认）、`on-failure:N`（异常退出才重启，限次数）、`always`（总是重启）、`unless-stopped`（类似 always 但手动 stop 不重启）。生产推荐 `unless-stopped`。

- 关键词：**unless-stopped 尊重手动停止**

**Q48: 怎么把本机镜像搬到离线服务器？**

**答：** `docker save -o img.tar 镜像` 导出成 tar，拷过去 `docker load -i img.tar` 导入。注意 `save` 是镜像的，`export` 是容器的（别混）。

- 关键词：**save/load 离线搬运镜像**

**Q49: 怎么备份一个卷的数据？**

**答：** 用临时容器 + tar：`docker run --rm -v 卷名:/data -v $(pwd):/backup alpine tar czf /backup/bak.tar.gz -C /data .`。恢复反过来解压。`--rm` 让临时容器用完即删。

- 关键词：**临时容器 + tar 备份**

**Q50: 容器和镜像分别怎么"瘦身/清理"？**

**答：** 镜像瘦身：alpine + 多阶段 + 合并 RUN + .dockerignore。容器清理：`docker container prune`（清 exited 容器）；镜像清理：`docker image prune`（清无标签的 dangling 镜像）；卷清理：`docker volume prune`（清孤儿卷）。

- 关键词：**prune 三连：container / image / volume**

## 二、白板手写题（Q51~Q60）

面试官说"来，写一个"的时候，**先讲思路再动手**——这是第一分。代码写了 80% 也比卡住强，边写边说话。

### 1. 读命令说结果（3 题）

**Q51: 执行下面的命令，第二行输出什么？**

```bash
docker run -d --name web nginx
docker run -d --name web nginx
```

**答：** 报错：

```text
docker: Error response from daemon: Conflict. The container name "/web" is already in use by container "a1b2c3d4e5f6". You have to remove (or rename) that container to be able to reuse that name.
```

- 关键：容器名唯一，同名冲突

**Q52: 执行下面的命令，`docker ps` 能看到容器吗？为什么？**

```bash
docker run nginx
# 按 Ctrl+C 退出
docker ps
```

**答：** 看不到。`docker ps` 只显示**运行中**的容器，Ctrl+C 把容器停了（状态 exited）。要用 `docker ps -a` 才能看到它。

- 关键：`ps` 只看 running，`-a` 看全部

**Q53: 下面 Dockerfile 构建后，`docker run 镜像 other.js` 实际执行什么？**

```dockerfile
FROM node:22-alpine
ENTRYPOINT ["node"]
CMD ["server.js"]
```

**答：** 执行 `node other.js`。因为 `ENTRYPOINT` 是固定命令（node），`docker run` 末尾的 `other.js` 替换的是 `CMD`（默认参数），不替换 ENTRYPOINT。

- 关键：ENTRYPOINT 定命令、CMD 定默认参数，末尾参数替换 CMD

### 2. 手写 Dockerfile（4 题）

**Q54: 怎么手写一个"工程化达标"的 Node 应用 Dockerfile（应用入口 server.js，监听 3000）？**

**答：**

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install --omit=dev
COPY . .
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
```

- 讲清：alpine（小）、依赖清单先 COPY（缓存）、只装生产依赖、CMD exec 形式（信号直达）

**Q55: 怎么手写一个多阶段构建的 Dockerfile（第一阶段构建产出 dist/，第二阶段运行）？**

**答：**

```dockerfile
FROM node:22 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

FROM node:22-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
ENV NODE_ENV=production
CMD ["node", "dist/server.js"]
```

- 讲清：每个 FROM 开一阶段，`COPY --from=builder` 只拷产物，工具链不进最终镜像

**Q56: 怎么手写一个能持久化的 postgres 启动命令（挂命名卷、设密码、后台）？**

**答：**

```bash
docker run -d --name db \
  -v pgdata:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=secret \
  postgres:16
```

- 讲清：命名卷持久化、`-d` 后台、`-e` 传密码

**Q57: 怎么手写一个 compose，编排 web（build 当前目录）+ db（postgres:16），db 挂卷、web 等 db 健康？**

**答：**

```yaml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  pgdata:
```

- 讲清：build vs image、命名卷、健康检查 + service_healthy

### 3. 机制讲清楚（3 题）

**Q58: 说清楚"构建缓存"的机制，以及为什么要"依赖清单先 COPY"？**

**答：** 每条指令算一个缓存键（指令内容 + 上一层 digest），从第一条变化的指令起往后全重建。`COPY` 的缓存键看**文件内容**。依赖清单（package.json）不常变，先 COPY 它再 `RUN npm install`，install 能长期命中缓存；源码常变放后面。反过来，每次改代码都重装依赖。

- 关键：**缓存键 = 指令 + 上层 digest；COPY 看文件内容**

**Q59: 说清楚容器"数据丢失"的机制，以及卷怎么解决？**

**答：** 容器启动时 OverlayFS 在最上面加一层**可写层**，所有写入都进这一层，镜像的只读层不动。`docker rm` 时可写层随容器销毁，所以数据没了。卷（volume）是独立于容器的存储（`/var/lib/docker/volumes/`），数据写进卷而非可写层，删容器后卷还在，重挂载数据"回来"。

- 关键：**可写层随容器销毁，卷独立于容器**

**Q60: 说清楚"容器名互访"的原理，为什么默认 bridge 不行？**

**答：** 自定义网络内置一个 DNS（127.0.0.11），容器名会自动注册，容器间访问容器名时由 DNS 解析成 IP。IP 会变但名字不变，所以用名字连接稳定。默认 bridge 是 Docker 最老的实现，没带这个 DNS，所以只能靠 IP 互访。`--link` 是更早的单向静态机制，已被取代。

- 关键：**内置 DNS + 容器名注册；默认 bridge 无 DNS**

### compose 命令速查

| 我想做的事 | 命令 |
|---|---|
| 启动整套 | `docker compose up -d` |
| 重新构建并启动 | `docker compose up -d --build` |
| 停止并清理 | `docker compose down` |
| 连卷一起删（危险） | `docker compose down -v` |

### Dockerfile 指令速查

| 指令 | 作用 | 关键点 |
|---|---|---|
| `FROM` | 基础镜像 | 第一条；多阶段可多个 |
| `WORKDIR` | 工作目录 | 不存在自动建 |
| `COPY` | 复制文件进镜像 | 只能取上下文里的文件 |
| `ADD` | COPY 加强版 | 自动解压 tar + URL，少用 |
| `RUN` | 构建时执行命令 | 产出一层；多命令用 `&&` 合并 |
| `ENV` | 环境变量 | 构建运行时都生效 |
| `EXPOSE` | 声明端口 | 只是元数据，不开端口 |
| `CMD` | 默认启动命令 | 可被覆盖，用 exec 形式 |
| `ENTRYPOINT` | 固定启动命令 | 末尾参数变成它的参数 |

### 真实报错速查

| 报错（原文） | 触发原因 | 怎么修 |
|---|---|---|
| `Unable to find image 'xxx:latest' locally` | 本地没这个镜像（会自动拉取） | **不是报错**，等它拉完 |
| `Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?` | daemon 没启动 | 开 Docker Desktop / `systemctl start docker` |
| `COPY failed: file not found in build context or excluded by .dockerignore: stat xxx: file does not exist` | COPY 的源不在构建上下文 | 检查 build 目录和 .dockerignore |
| `manifest for xxx:tag not found: manifest unknown` | tag 不存在 | 检查 tag 拼写 |
| `Conflict. The container name "/xxx" is already in use` | 容器名重复 | 换名或先删 |
| `Bind for 0.0.0.0:8080 failed: port is already allocated` | 宿主端口被占 | 换端口 |
| `You cannot remove a running container xxx` | 删运行中的容器 | 先 stop 或 `rm -f` |
| `conflict: unable to delete xxx - image is being used by stopped container` | 有停止的容器用这个镜像 | 先删容器再删镜像 |
| `volume is in use - [容器id]` | 删在用卷 | 先删容器再删卷 |
| `network xxx not found` | 网络不存在 | 先 `docker network create` |
| `no matching manifest for linux/arm64/v8` | 架构不匹配 | 用 `--platform` 指定架构 |
| `the input device is not a TTY` | 非终端环境用了 `-t` | CI 里去掉 `-t` |

### 退出码速查

| 退出码 | 含义 |
|---|---|
| `0` | 正常退出 |
| `1` | 一般错误 |
| `137` | 被 SIGKILL 强杀（kill / OOM） |
| `143` | 收到 SIGTERM 优雅退出 |

### 端口映射速查

| 写法 | 含义 |
|---|---|
| `-p 8080:80` | 宿主 8080 → 容器 80 |
| `-p 127.0.0.1:8080:80` | 只绑本机 8080 |
| `-P` | 映射所有 EXPOSE 端口到随机宿主端口 |

## 四、面试技巧

### 4.1 不会的时候怎么救场

**核心原则：把"不知道"换成一个有价值的过程。**

- ❌ 别硬编答案。说出一句错的原理，比说"我不确定"伤害大得多。
- ✅ 可以说：**"这个命令我记不太准，但我知道它要解决的是 X 问题。能让我说下我的思路吗？"**
- ✅ 把问题**降维到你会的那一层**：不会答"多架构镜像的 manifest"，就说"我理解它是解决'同一个镜像名在不同 CPU 架构下内容不同'的问题，我用过的是 `--platform` 指定架构"。
- ✅ 明说**边界**："这块我目前只到会用，没深入看过实现。"诚实 + 说明掌握程度，好过硬撑。

**三句万能救场句：**

1. "我先说结论，再说为什么，可以吗？"
2. "我没遇到过这个具体场景，我的推理是这样的……"
3. "这个点我回去会补，能说说你们实际是怎么处理的吗？"

### 4.2 可以反问什么

面试的最后环节，**反问的质量常常决定印象分**。按目标挑 2~3 个：

**想了解团队与工程成熟度：**

- 团队现在部署是容器化还是虚拟机？Docker/K8s 用到什么程度？
- 你们的 CI 流程里有没有镜像扫描（scout/trivy）？
- 镜像仓库是自建（Harbor）还是用云服务？

**想了解技术挑战与成长：**

- 目前你们最头疼的 Docker/容器化问题是什么？
- 最近一次"环境不一致"导致的事故，是怎么解决的？
- 新人入职前三个月，通常会遇到什么挑战？

**想了解协作方式：**

- 服务是"一个容器一个服务"吗？还是用了其它编排（K8s）？
- 数据库这类有状态服务，你们是容器化还是单独管理？为什么？

**反向加分项（显示你懂工程）：**

- "你们怎么处理'容器里的日志'？是 stdout 收集还是 agent 读文件？"
- "数据库容器的持久化和备份，你们是怎么做的？"

**别问的：** 薪资细节（留给 HR 环节）、能在官网查到的公开信息、以及"你们用 Docker 吗"这种能自己判断的。

### 4.3 现场写代码的 5 个习惯

1. **先复述需求 + 确认边界。** "我理解是要一个 Node 应用的 Dockerfile，需要缓存友好、非 root，对吗？要健康检查吗？"——这一步就能拉开差距。
2. **先讲思路再敲代码。** "我打算用 alpine 基础镜像，依赖清单先 COPY……"讲完再动手。
3. **命名要清楚。** 服务名、卷名（`pgdata`）、镜像 tag（`myapp:1.0`）——面试官看的就是这些细节。
4. **主动指出取舍。** "这里我用了 `depends_on`，但如果要保证数据库就绪，我会加 healthcheck。"主动说，比被问出来强十倍。
5. **写完主动自检。** "这里有个边界：`COPY . .` 会把 node_modules 也拷进去，所以我会加 `.dockerignore`。"——展示你有"运行时"的意识。

### 4.4 高频陷阱题识别

| 听到这个问法 | 真正考的是什么 |
|---|---|
| "容器和虚拟机有什么区别？" | 你敢不敢说"容器共享内核"，以及能不能说清代价 |
| "`latest` 能用于生产吗？" | 你知不知道 tag 会漂移、不可复现 |
| "`EXPOSE` 会开放端口吗？" | 你知不知道它只是声明，`-p` 才真正开放 |
| "`CMD` 和 `ENTRYPOINT` 有什么区别？" | 你知不知道"可覆盖 vs 只能追加参数" |
| "为什么 build 每次都重装依赖？" | 你有没有"缓存键"的直觉——依赖清单要先 COPY |
| "`docker ps` 看不到我的容器" | 你知不知道 `-a` 和 running/exited 的区别 |
| "`depends_on` 能等数据库就绪吗？" | 你知不知道"顺序 ≠ 就绪"，healthcheck |
| "`docker rm` 会删数据吗？" | 你知不知道可写层 vs 卷 |

**最后一条提醒：** 面试官真正想知道的只有两件事——**你能不能把"镜像 → 容器 → 编排"这条主线讲清楚**，以及**出问题时你能不能自己找到原因**。所有题目都是这两件事的变体。

> 一句话记住它：**面试考的不是"你知道多少"，而是"你能不能把为什么讲清楚"。**
