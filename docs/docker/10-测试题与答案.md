## 第一关 · 概念快问快答（20 题）

判断下面每句话是**对**还是**错**。不要猜，想清楚理由。

1. 镜像是只读的，容器是可写的、可销毁的运行实例。
2. 容器就是一台"轻量级虚拟机"，每个容器里都跑着一个完整的操作系统。
3. 容器里的数据默认写在"可写层"，删除容器后这些数据就没了。
4. `docker run` 等价于 `docker create` + `docker start` + `docker attach`。
5. `docker ps` 会列出所有状态的容器，包括已停止的。
6. 一个镜像是由多层只读层从下往上叠加而成的。
7. `latest` 标签代表这个镜像的最新版本。
8. 在 Dockerfile 里写了 `EXPOSE 3000`，容器启动后宿主就能直接访问 3000 端口。
9. `RUN` 指令会在容器运行时执行。
10. `CMD` 用 shell 形式（`CMD node server.js`）时，容器的 PID 1 是 `/bin/sh` 而不是 node。
11. Dockerfile 里先 `COPY . .` 再 `RUN npm install`，改一行源码会导致重新安装依赖。
12. 在自定义网络里，容器可以直接用容器名互相访问。
13. 在默认 bridge 网络里，容器可以直接用容器名互相访问。
14. `-p 8080:80` 表示把宿主机的 80 端口映射到容器的 8080 端口。
15. bind mount 和 volume 都能持久化数据，区别是 bind mount 用宿主的绝对路径、volume 由 Docker 管理。
16. `docker rm 容器` 会连同它挂载的命名卷一起删除。
17. `depends_on` 能保证被依赖的服务完全就绪后，才启动当前服务。
18. `docker compose down` 会删除 compose 文件里声明的卷。
19. 多阶段构建可以让最终镜像不包含编译器、dev 依赖等构建工具链。
20. 容器默认以 root 用户运行，生产环境建议切到非 root 用户。

## 第三关 · 改错（10 题）

每题给你一段**能跑出问题**的代码/命令。先别看修正，自己找。

### 3.1 数据随容器一起没了

**问题代码：**

```bash
docker run -d --name db postgres:16
# 写入数据……
docker rm db
docker run -d --name db2 postgres:16
# 数据全没了！
```

**症状：** 删掉容器重开，数据库数据丢失。

**为什么：** 数据写在容器的**可写层**，`docker rm` 时随容器一起销毁。要持久化，必须挂卷。

**修正代码：**

```bash
docker run -d --name db -v pgdata:/var/lib/postgresql/data postgres:16
# 写入数据……
docker rm db
docker run -d --name db2 -v pgdata:/var/lib/postgresql/data postgres:16
# 数据还在（在卷 pgdata 里）
```

### 3.2 COPY 找不到文件

**问题代码：**

```dockerfile
FROM node:22-alpine
COPY /etc/passwd /app/passwd
```

**症状：** 构建报错：

```text
COPY failed: file not found in build context or excluded by .dockerignore: stat /etc/passwd: file does not exist
```

**为什么：** `COPY` 的源路径是**相对构建上下文**的，不是相对宿主机根目录。上下文里没有 `/etc/passwd`。

**修正代码：** 把要复制的文件放进构建上下文（`docker build` 指定的目录）里，再 COPY：

```dockerfile
FROM node:22-alpine
COPY ./passwd /app/passwd
```

### 3.3 改了代码还是重装依赖

**问题代码：**

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
RUN npm install
CMD ["node", "server.js"]
```

**症状：** 每改一行源码，`npm install` 都重新执行，build 很慢。

**为什么：** `COPY . .` 在 `RUN npm install` 之前，源码一变这层失效，后面的 install 也失效重跑。

**修正代码：**

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
CMD ["node", "server.js"]
```

### 3.4 端口映射写反

**问题代码：**

```bash
docker run -d -p 80:8080 nginx
curl http://localhost:80
# 连不上！
```

**症状：** 访问宿主 80 连不上。

**为什么：** `-p 宿主:容器`，这里宿主 80 转发到容器 8080，但 nginx 在容器里默认监听的是 **80**，8080 没人监听。

**修正代码：**

```bash
docker run -d -p 8080:80 nginx
curl http://localhost:8080
```

### 3.5 容器名冲突

**问题代码：**

```bash
docker run -d --name web nginx
docker run -d --name web nginx
```

**症状：** 第二条命令报错：

```text
docker: Error response from daemon: Conflict. The container name "/web" is already in use by container "a1b2c3d4e5f6". You have to remove (or rename) that container to be able to reuse that name.
```

**为什么：** 容器名唯一，同名容器已存在。

**修正代码：** 换名字，或先删旧的：

```bash
docker rm -f web
docker run -d --name web nginx
```

### 3.6 用 RUN 启动服务

**问题代码：**

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
RUN node server.js
```

**症状：** 构建时卡住（node 前台运行不退出），或构建完容器起来后立刻退出。

**为什么：** `RUN` 是**构建时**执行的，不是运行时。用 `RUN node server.js` 等于在 build 阶段就启动服务，且它跑完（或阻塞）都不对。

**修正代码：** 启动服务用 `CMD`/`ENTRYPOINT`：

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
CMD ["node", "server.js"]
```

### 3.7 以为 EXPOSE 能开放端口

**问题代码：**

```dockerfile
FROM nginx
EXPOSE 80
```

```bash
docker run -d --name web my-nginx
curl http://localhost:80    # 连不上！
```

**症状：** 宿主机访问不到。

**为什么：** `EXPOSE` 只是声明端口（元数据），不真正开放。

**修正代码：** 真正开放靠 `-p` 映射：

```bash
docker run -d --name web -p 8080:80 my-nginx
curl http://localhost:8080
```

### 3.8 默认 bridge 里用容器名互访

**问题代码：**

```bash
docker run -d --name db postgres:16
docker run -d --name web myapp      # web 里用 "db" 连接
# web 里报错：getaddrinfo ENOTFOUND db
```

**症状：** web 里解析不了 `db`。

**为什么：** 默认 bridge 网络没有内置 DNS，容器名不能互访（只能 IP）。

**修正代码：** 用自定义网络：

```bash
docker network create my-net
docker run -d --name db --network my-net postgres:16
docker run -d --name web --network my-net myapp
```

### 3.9 以为 depends_on 会等就绪

**问题代码：**

```yaml
services:
  web:
    depends_on:
      - db
  db:
    image: postgres:16
```

**症状：** `up` 后 web 服务反复报"连接数据库失败"，重启几次才好。

**为什么：** `depends_on` 只保证"先启动 db 容器"，不保证 db 已就绪（postgres 起来后还要几秒初始化）。

**修正代码：** 加健康检查 + `service_healthy`：

```yaml
services:
  web:
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5
```

### 3.10 `down -v` 误删数据

**问题代码：**

```bash
docker compose down -v    # 以为只是"停服务"
```

**症状：** 数据库数据全没了。

**为什么：** `down -v` 会**连卷一起删**，卷里存的数据就没了。

**修正代码：** 只是想停服务，用 `down`（不带 `-v`）：

```bash
docker compose down       # 停服务，保留卷和数据
```

| 3 | 每次改代码重装依赖 | `COPY . .` 在 install 之前 | 依赖清单先 COPY，install 再 COPY 源码 |
| 4 | 访问宿主 80 连不上 | `-p` 左右写反 | `-p 8080:80`（宿主:容器） |
| 5 | `Conflict ... already in use` | 容器名重复 | 换名或先 `docker rm -f` |
| 6 | build 卡住/容器秒退 | `RUN` 是构建时执行的 | 启动用 `CMD` |
| 7 | 宿主访问不到容器 | `EXPOSE` 只声明不开放 | 用 `-p` 映射 |
| 8 | `getaddrinfo ENOTFOUND db` | 默认 bridge 无 DNS | 用自定义网络 |
| 9 | web 起太早连不上 db | depends_on 不等就绪 | healthcheck + `service_healthy` |
| 10 | `down -v` 数据全没 | `-v` 连卷删 | 用 `down`（不带 `-v`） |

## 第四关 · 面试问答（15 题）

出声讲一遍，不要在心里默读。每题下方的引用块是**面试官真正想听到的点**。

### 第 1 题

**Q：用一句话说清镜像、容器、仓库的关系。**

**A：** 镜像是只读的构建产物（类），容器是镜像运行起来的实例（实例），仓库是存放镜像的远端（registry）。`docker pull` 从仓库拉镜像，`docker run` 把镜像跑成容器，`docker push` 把镜像推回仓库。

> **面试官想听到的要点：** 三个词 + 它们之间的"搬运"关系；最好能类比 npm（registry / 包 / 运行）。

### 第 2 题

**Q：容器和虚拟机有什么区别？为什么容器更快？**

**A：** 虚拟机虚拟的是**硬件**（每个虚机跑一个完整 Guest OS），容器虚拟的是**操作系统视图**（复用宿主内核，用 namespace + cgroup 隔离）。所以容器启动 = 启动一个被圈起来的进程，毫秒级；虚拟机要启动一整个 OS，几十秒。代价是容器隔离性弱、且必须与宿主同内核。

> **面试官想听到的要点：** "虚拟硬件 vs 虚拟 OS 视图"；提到 namespace/cgroup；能说出代价（隔离弱、同内核）。

### 第 3 题

**Q：镜像为什么是"分层"的？分层带来什么好处？**

**A：** 镜像是一串只读层叠起来的，每层记录"相对上一层的文件系统变化"。好处是**复用**：多个镜像共享同一底层只下载/存一份；构建时改代码只需重建最上面几层（层缓存）；层靠 sha256 内容寻址，内容相同即可复用、可校验。

> **面试官想听到的要点：** "层 = 增量"；提到复用（下载省、存储省、构建快）；最好提一句内容寻址。

### 第 4 题

**Q：`docker run` 背后做了什么？它和 `create`/`start` 什么关系？**

**A：** `docker run` = `docker create`（创建容器）+ `docker start`（启动）+ `docker attach`（前台附着）。找不到镜像时会自动 pull。理解这个拆解，就知道"run 的参数在创建时定死，不能改，只能重建"。

> **面试官想听到的要点：** run = create + start + attach；提到"参数定死不能改"。

### 第 5 题

**Q：`-it` 里 `-i` 和 `-t` 分别是什么？**

**A：** `-i`（interactive）保持 stdin 打开，让容器能**输入**；`-t`（tty）分配伪终端，让输出有**交互格式**（提示符、光标）。交互式 shell/REPL 需要两者。非终端环境（CI）用 `-t` 会报 `the input device is not a TTY`。

> **面试官想听到的要点：** 两个参数各管一半（输入 vs 显示）；知道 CI 里的坑。

### 第 6 题

**Q：`CMD` 和 `ENTRYPOINT` 的区别？**

**A：** `CMD` 是默认启动命令，能被 `docker run` 末尾参数**整体覆盖**；`ENTRYPOINT` 是固定命令，末尾参数**不覆盖它、只变成它的参数**。组合时 ENTRYPOINT 定命令、CMD 定默认参数。两者都推荐 exec 形式（信号直达）。

> **面试官想听到的要点：** "可覆盖 vs 只能追加参数"；能举 ENTRYPOINT 做"命令工具"的例子。

### 第 7 题

**Q：`COPY` 和 `ADD` 有什么区别？为什么推荐 COPY？**

**A：** `ADD` 比 `COPY` 多了两个能力：自动解压 tar、支持 URL。但这俩能力容易惹祸（行为隐形、引入不确定性），所以官方建议能用 COPY 就用 COPY。

> **面试官想听到的要点：** 知道 ADD 多出来的能力，以及为什么不推荐。

### 第 8 题

**Q：`EXPOSE` 和 `-p` 的区别？**

**A：** `EXPOSE` 只是**声明**端口（写进镜像元数据），不真正开放；`-p 宿主:容器` 才真正做端口映射，`-P` 映射所有 EXPOSE 声明的端口到随机宿主端口。

> **面试官想听到的要点：** "声明 vs 真正开放"；能说清 `-p` 和 `-P` 的区别。

### 第 9 题

**Q：容器之间怎么通信？默认 bridge 和自定义网络有什么区别？**

**A：** 自定义网络里，容器直接用**容器名**互访（内置 DNS）；默认 bridge 是旧实现，没有 DNS，只能靠 IP 互访。所以多容器互联用自定义网络。`--link` 是更早的机制（单向、静态、有顺序要求），已被自定义网络取代。

> **面试官想听到的要点：** 容器名互访靠内置 DNS；知道 link 已过时。

### 第 10 题

**Q：容器的数据会丢吗？怎么持久化？**

**A：** 容器的可写层随容器删除而销毁，所以数据默认会丢。持久化两种方式：**volume**（Docker 管理，`-v 卷名:路径`，生产存数据）和 **bind mount**（挂宿主绝对路径，`-v /host:容器`，开发热更）。`docker rm` 不删卷，命名卷数据在容器删除后仍在。

> **面试官想听到的要点：** 两种方式 + 各自场景；知道"rm 不删卷"。

### 第 11 题

**Q：匿名卷和命名卷有什么区别？**

**A：** `-v /data`（只写容器路径）创建**匿名卷**，Docker 起随机名，难管理，容器删后变孤儿卷堆积；`-v pgdata:/data` 是**命名卷**，有名字好管理。日常用命名卷，孤儿卷用 `docker volume prune` 清理。

> **面试官想听到的要点：** 写法区别 + 匿名卷的堆积问题。

### 第 12 题

**Q：`depends_on` 能保证服务就绪吗？不能的话怎么办？**

**A：** 不能。`depends_on` 只保证启动**顺序**，不保证被依赖服务已**就绪**（如数据库初始化完成）。要等就绪：给服务加 healthcheck，`depends_on` 用 `condition: service_healthy`；简单场景可用 `restart: on-failure` 重试。

> **面试官想听到的要点：** "顺序 vs 就绪"的区分；能说出 healthcheck + service_healthy。

### 第 13 题

**Q：什么是多阶段构建？它解决什么问题？**

**A：** 一个 Dockerfile 里多个 `FROM`，每个 FROM 开一个新阶段；最终镜像只含最后一个阶段。构建工具（编译器、dev 依赖）只在第一阶段，`COPY --from` 把产物拷到运行阶段。解决"构建工具和运行时依赖不分"导致的镜像臃肿 + 攻击面大。

> **面试官想听到的要点：** 多个 FROM + COPY --from；提到体积和攻击面两个收益。

### 第 14 题

**Q：怎么减小镜像体积？说三个方法。**

**A：** 1) 换 alpine/slim 基础镜像（立减 80%）；2) 多阶段构建（工具链不进最终镜像）；3) `.dockerignore` 减小构建上下文；外加：合并 RUN、只装生产依赖、装完即清理。

> **面试官想听到的要点：** 至少说出 alpine + 多阶段 + .dockerignore 三个。

### 第 15 题

**Q：容器默认以什么用户运行？有什么安全隐患？怎么改？**

**A：** 默认 **root**。root 权限大，应用被攻破后攻击者拿到的是容器里的 root，危害更大。改法：先 root 做完安装，最后 `USER` 切到非 root 用户运行（最小权限原则）。

> **面试官想听到的要点：** "最小权限"；知道先装后切的顺序。
